Petrinaut has three parts, and each part is cut into blocks. A block is a folder that declares a layer, together with the sub-layers its row names. The tables list the blocks of each part in the order to learn them. **Imported through** names the files that code outside the block imports. The Core table leaves out a file that only a package entry or a worker entry re-exports, except the block's own entry file. The other two tables count every importer, so a `provider.tsx` that only the entry of the React layer mounts is listed. **Protocol** names a contract the block owns, such as a worker channel, a context value, a store shape or a lifecycle, and links to where it is written. **Guide** links the pages about the block, and "README" opens the layer page, which shows the README of the folder. An empty cell says the block has none: no file that carries its imports, no protocol written outside its comments, or no guide.

![The host imports the editor and the preview from the UI and handles from Core. The UI imports the React layer and Core, the React layer imports Core, and Core imports neither. Core reaches its workers through messages.](@diagrams/building-blocks.svg)

`@hashintel/petrinaut` publishes the React layer and the UI through the entries of its [package layer](layer:petrinaut): `src/main.ts` for a host, `src/preview.ts` for the preview and `src/panda-preset.ts` for a host's stylesheet. Rules of `archinaut check` hold the directions of the diagram, and the [Architecture](architecture) page lists them.
