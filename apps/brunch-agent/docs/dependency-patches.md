# Brunch's dependency contracts and patch ownership

Brunch upgrades Flue and Pi together. The remaining patches preserve native tool validation, model-only context projection, and complete Anthropic schemas. They do not change the default model or replace the transport's reattachment and browser-ordering contracts.

The package manifests and root resolutions name the installed versions. Patch selectors must cover both direct Pi pins and the ranges Flue and agent-core request; a version bump that misses a selector can silently install an unpatched copy, which `test/dependency-patch-resolution.test.ts` rejects. `.yarnrc.yml` also supplies the Standard Schema dependency used by Flue's patched public types. An exact-release age-gate exception for this upgrade expires after the approved releases age out; keep the general seven-day gate.

## Retained contracts

| Boundary and owner                                    | Why Brunch still owns it                                                                                                                                                                                                                                                                                                                                                                                                  | Removal condition and proof                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native input schemas — Flue runtime and Pi agent-core | Petrinaut supplies executable Standard Schema validators and their Standard JSON Schema input descriptions. Defaults, transforms and refinements cannot be replaced by generic JSON Schema coercion. The native validator is authoritative, runs once, and passes its parsed output to execution without rewriting recorded arguments. Cancellation prevents execution; durable re-execution uses the same native parser. | Upstream must offer equivalent schema input and authoritative validation before `beforeToolCall`. Pi 1.2.0's existing hook runs after generic validation, so it is not equivalent. Prove native parsing, rejection, cancellation and recovery through the real Flue/Pi loop before removing either half. |
| Model-context projection — Flue runtime               | `useContextProjection` gives Brunch canonical entry IDs and structured signals, so it can hide host-only envelopes and show the relevant net read-back. Each compaction consumer sees only its own entries. Canonical/public history is unchanged. Pi's transcript-leading system message remains outside the projection.                                                                                                 | A public Flue extension must preserve those identities, exact slices, history and reopen semantics. A provider-level message rewrite alone is insufficient. Run projection, compaction, net-freshness and Ledger-history tests.                                                                          |
| Complete Anthropic `input_schema` — Pi AI             | Non-strict and strict-prefer fallback conversion still drops top-level JSON Schema fields upstream. Brunch keeps the complete selected parameter schema independently of constrained-generation policy. The one conversion patch covers request-level and inline declarations, including OAuth name conversion.                                                                                                           | Upstream must preserve complete schemas on every declaration path and strict fallback. Local HTTP payload tests must prove `$defs`/`$ref`, `additionalProperties`, declarations/redefinitions and final-request accounting.                                                                              |

These are upstream candidates, not claims that upstream proposals have been filed or accepted. FE-1765 tracks the dispositions and FE-1799 tracks the coordinated upgrade. The authoritative upstream code is [Flue 2.3.0](https://github.com/withastro/flue/tree/v2.3.0) and [Pi 1.2.0](https://github.com/earendil-works/pi/tree/v1.2.0).

The Anthropic `onPayload` hook is supported, but replacing the conversion patch would require reconstructing historical tool definitions, matching OAuth names and placeholders, handling strict fallback, and composing with accounting. That is more local machinery than the narrow conversion change. Keep the patch until upstream fixes schema carriage; do not introduce a general payload-repair subsystem to remove a patch file.

## Removed interventions

| Previous intervention                                   | Disposition                                                                                                                                                                                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Atomic repair batch                                     | Removed after testing stock Flue's separate outcome and result-commit appends, including a kill in the gap. The crash audit checks one outcome record, its result-commit association, stable IDs and no replay rather than requiring one append.        |
| Persistent hook-state buffering and setter ordering     | Removed: no production consumer remains in the scoped Brunch packages. The private-buffer ordering test is not a product durability contract. Ledger recovery is checked separately.                                                                    |
| Flue `prepareArguments` plumbing                        | Removed: no Brunch tool uses it. Native schemas own parsing. Pi's own upstream `prepareArguments` API is untouched.                                                                                                                                     |
| Successful-response overflow backport                   | Removed: Flue fixed this in 2.0.7. Regression coverage must still prove that compaction does not repeat a completed model response or tool execution.                                                                                                   |
| Pi validate-first `anyOf`/`oneOf` backport              | Removed: upstream since 0.84.0. Native inputs still use their own validator.                                                                                                                                                                            |
| Flue root export of the retry marker                    | Replaced by the documented `(retryable_interruption)` protocol value in provider admission. Flue's published errors reference makes the string value the contract. The bounded pre-tool retry policy remains; completed browser work is never replayed. |
| Copied GPT-6 Sol catalogue entries                      | Removed in favour of Pi's catalogue. Only the missing `gpt-5.5-2026-04-23` snapshot alias remains, derived from the undated entry. The default model is unchanged.                                                                                      |
| App-only `pi-tui`, `typebox`, and `md-pen` declarations | Removed: they have no direct app consumer. `md-pen` stays in the shared library, which uses it. The app's JSON Schema converter is test-only and is a dev dependency.                                                                                   |

The dated default derives its metadata from Pi's `gpt-5.5` entry because [OpenAI's model page](https://developers.openai.com/api/docs/models/gpt-5.5) maps that alias to `gpt-5.5-2026-04-23` (checked 2026-10-14). Capability flags come from Pi's catalogue, not a separate Brunch model declaration. Local serialization tests verify their request shapes; they do not prove provider acceptance. Recheck the alias mapping on the next Pi upgrade before inheriting updated metadata for this fixed snapshot.

## Outside this patch boundary

The root `@anthropic-ai/bedrock-sdk/@anthropic-ai/sdk` resolution belongs to the AI worker, not Brunch. It aligns the worker's Bedrock adapter with its direct Anthropic SDK. Retain it until an AI-worker-scoped fresh solve, typecheck and client tests justify removal; this upgrade does not reopen the retired provider investigation.

Flue 2.3.0 does not replace the transport's outer stream reattachment, tool-input delta side channel, or same-proposal dependency admission. It also does not forward Pi's per-tool `executionMode`. See the [transport compatibility record](../../../libs/@local/flue-aisdk-transport/README.md) for the wire/reducer proof rather than treating a version-baseline assertion as compatibility evidence.

Validation and tool execution have separate `timeoutMs` budgets: asynchronous parsing is bounded before the normal execution clock starts. The canonical-context projector is verified for Brunch's conversational tools; Flue result-schema prompt mode and its live-only reminder messages are outside that verified path.

## Verification

Run the affected builds before the integration suites: they import the actual built application. The package scripts define unit tests, typechecks and lints. The Brunch app's integration suite covers Ledger history/crash recovery, compaction, guidance and admission; `@tests/petrinaut-brunch-integration` exercises the panel against the built server. Provider payload tests use a local synthetic HTTP endpoint, not paid model calls. Run `yarn constraints` and an immutable install to verify package alignment and patch application, then run the manual browser witnesses. Set `BRUNCH_RETAIN_CRASH_ARTIFACTS=1` when running the app integration suite to retain passing Ledger crash evidence as well as failures. A paid persona run requires separate authorization.
