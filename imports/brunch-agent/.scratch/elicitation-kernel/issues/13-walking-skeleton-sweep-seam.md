## Question

Prove the four substrate capabilities the capture-sweep machinery assumes but no prototype has exercised on Flue — the unproven seam between ticket 10's transport skeleton and ticket 11's synthetic-log logic-prototype, surfaced by the [2026-08-10 consistency pre-pass](../notes/consistency-prepass-2026-08-10.md) (items L1–L3):

1. **Settlement trigger** — a substrate lifecycle event (turn-end / agent-settled) that invokes the agent's settlement judgment. Ticket 11 recorded this as "wiring proof delegated to ticket 10", but ticket 10 contains no settlement or lifecycle-event finding; the claim was a misattribution (L1).
2. **Read a session entry range** — harness code reading the entries it sweeps. Ticket 01 found no documented path to Pi's message list from inside a Flue agent; ticket 10 proved read-back only on the ui side via `useFlueAgent`; ticket 11 ran against a synthetic log. The hinge between the two prototypes is proven nowhere (L2).
3. **Inject an on-behalf-of-user state entry** — the carrier for ticket 12's re-entry briefing. Candidate: Flue's `kind: 'signal'` message with trusted-code attributes (ticket 01 §6), which would also yield the true-user-versus-injected provenance distinction for free.
4. **Transactional durable store distinct from per-conversation state** — ticket 12 requires whole-sweep-atomic application (and refusals) across sessions; conversation-scoped `usePersistentState` cannot provide it (ticket 01).

Success = a minimal Flue walking skeleton (seeded from `prototype/10-flue-roundtrip`) that wires ticket 11's pure reducer (`prototype/11-capture-sweep`) to a real session log through these four capabilities. The resolution amends Shipping shape's six-item substrate-capability list — these are its four missing entries (pre-pass L3) — or records what Flue lacks or forbids and what the Flue binding must therefore absorb (binding-size asymmetry is expected, per ticket 06).

## Comments

**2026-08-10 (walking skeleton built — awaiting your reaction; HITL).** The skeleton is done and all four capabilities were exercised against the real runtime, live model turns included. **Provisional verdict: all four hold on Flue — two absorbed by the binding as expected, none forbidden.**

**Assets** (branch `prototype/13-sweep-seam`, commit 276c0e4, `prototypes/sweep-seam/`): real Flue agent + web UI with a live target-document panel (`bun run dev`, sessions `?id=session-a`/`session-b` share target-document `demo`); `node probe-seam.mjs` re-runs 18 checks (all passing). README documents the ask/terminate and restart probes.

**Per capability:**

1. **Settlement trigger — PROVEN, native.** `useAgentFinish` is exactly the would-stop seam ticket 11 needed: awaited before the response settles, `ctx.append` steers a `settlement-check` signal into a same-response continuation turn, the hook re-fires at the next would-stop, and the response settles only when nothing appends. Trigger computes the facts (numbered unswept tail); judgment stays with the agent (declining is legal). Two mechanism findings: (a) the hook **fires on `terminate: true` suspensions too**, so the pending-affordance guard is load-bearing — without it the nudge would append into a suspended ask turn; (b) the nudge itself becomes a session entry, so the trigger must be **loop-guarded** (don't re-nudge the same max-user-seq; persistent `lastNudgedAt`).
2. **Read a session entry range — PROVEN, binding-absorbed.** No in-process path from agent code to the conversation store exists (the runtime getter is private; lifecycle contexts expose only tool names). The binding reads the **public durable-history projection** — `GET <agent-url>?view=history` via `@flue/sdk` — over self-HTTP; works mid-response (both the finish hook and the sweep tool read during the live response). The projection is sweep-sufficient: stable ids, stream order (seq), **`purpose` as the provenance discriminator** (`user` / `assistant` / `dispatch` / `advisory`), signal descriptors, tool parts with validated outputs. Warts: the binding must know its own base URL (env var here); a mid-flight read sees the partial assistant message; >1000-entry paging unprobed. Live-model finding: **entry-seq citation is error-prone for a small model** — the typed refusal steered a mis-cited sweep to correct in two hops (backpressure works), but the spec may prefer harness-resolved excerpt anchoring over model-chosen seqs.
3. **Inject an on-behalf-of-user state entry — PROVEN, native.** Two carriers share one vocabulary: `ctx.append` (same-response, no delivery) and `dispatch({kind: 'signal'})` (real delivery). Caller-defined signals project as system-role, `purpose: 'dispatch'`, `display: 'diagnostic'`, with `tagName` + trusted `attributes` — **structurally distinct from true user entries, so ticket 12's provenance rule is mechanically enforceable** (probe: a capture citing an injected entry is refused at validation). The re-entry briefing worked in all three shapes: fresh session, resumed session, and post-restart session — the last answered the user correctly from the briefing alone. Nuance: Flue classifies these as dispatch/diagnostic rather than literally "on behalf of the user"; the Pi convention survives as signal + render guidance, and the sharpened citable-evidence rule is *stronger* under Flue's classification.
4. **Transactional durable store — PROVEN as binding-owned; Flue neither provides nor forbids it.** `usePersistentState` is conversation-scoped by design; no cross-conversation store surface is public. The binding owns the target-document store (JSON file, tmp+rename atomic, in-process serialization — milestone-one local), and **every ticket-11 semantic survived contact with the real log**: whole-sweep-atomic apply/refuse, content-keyed idempotence, single-hop supersession as the stale-session guard (cross-session probe: session-b superseded session-a's capture; a stale re-supersession was refused with world-moved facts). Restart probe: conversations 404 (`stream_not_found` — in-memory, no `db.ts`), the store file survives. Confirms pre-pass L13: Flue's at-least-once tool re-execution makes content-keyed idempotence load-bearing, not optional.

**Proposed capability-list amendment** (Shipping shape 06 — its four missing entries, per pre-pass L3): 7. *subscribe to the would-stop lifecycle seam, with same-response signal steering* (native: `useAgentFinish`/`ctx.append`); 8. *read the session's durable entry projection, with provenance-discriminating entry kinds* (binding-absorbed: history route; no in-process API); 9. *inject typed non-user signal entries, both same-response and as deliveries* (native: append/dispatch, `kind: 'signal'`); 10. *provide a transactional durable store outside conversation state* (binding-absorbed entirely; Flue offers none). Binding-size asymmetry landed exactly where ticket 06 predicted — the Node binding absorbed 8 and 10.

**Incidental Flue facts:** `agentName` must be a string *literal* (the build-time scan rejects a constant reference); injected signals carry `display: 'diagnostic'`, so the ticket-10 UI-filtering lesson extends to them (the skeleton renders them as labeled cards instead — exploded-view-lite, per the map's fog note).
