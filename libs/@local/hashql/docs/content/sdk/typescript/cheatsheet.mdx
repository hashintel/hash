This guide is a quick reference for HashQL constructs across implementations. For each construct, you can view the equivalent in Rust, Python or TypeScript.

The [literal value cheatsheet](#literal) covers the construction of values in HashQL, while the [common program patterns cheatsheet](#control-flow) covers control flow constructs and special forms.

The TypeScript, Rust and Python tabs show either a program that you can run yourself to verify the output, or type declarations. Each runnable Draft example prints the J-Expr in the tab beside it. The functional and reference notations are illustrative, so the result shown for HashQL is the one the language specifies, written in reference notation. Refer to the [introduction](/docs/hashql/intro) to learn more about each form.

## At a glance [#at-a-glance]

| Form                  | Reference notation     | Functional notation   | TypeScript SDK                              |
| --------------------- | ---------------------- | --------------------- | ------------------------------------------- |
| [`struct`](#struct)   | `(x: e)`               | `(x: e)`              | `Program.Structural.struct({ x: e })`       |
| [`tuple`](#tuple)     | `(a, b)`               | `(a, b)`              | `Program.Structural.tuple([a, b])`          |
| [`list`](#list)       | `[a, b]`               | `[a, b]`              | `Program.Structural.list(T, [a, b])`        |
| [`dict`](#dict)       | `{k: v}`               | `{k: v}`              | `Program.Structural.dict(K, V, [[k, v]])`   |
| [`let`](#let)         | `let x = e in body`    | `(let x e body)`      | `$.let("x", e)`                             |
| [`if`](#if)           | `if c then a else b`   | `(if c a b)`          | `$.if(c, { then, else })`                   |
| [`input`](#input)     | `input(x, T)`          | `(input x T)`         | `Draft.program({ x: T }, ($, inputs) => e)` |
| [`fn`](#fn)           | `(x: T): R -> e`       | `(fn () (x: T) R e)`  | Not available                               |
| [`use`](#use)         | `use(path, (a: b), e)` | `(use path (a: b) e)` | `$.import(module, { a: "b" })`              |
| [`access`](#access)   | `e.field`, `e.0`       | ``(`.` e field)``     | `e.field`, `e[0]`                           |
| [`index`](#index)     | `e[i]`                 | `(index e i)`         | `e.$index(i)`                               |
| [`as`](#as)           | `e as T`               | `(as e T)`            | Not available                               |
| [`type`](#type)       | `type T = U in e`      | `(type T U e)`        | `$.type("T", U)`                            |
| [`newtype`](#newtype) | `newtype T = U in e`   | `(newtype T U e)`     | `$.newtype("T", U)`                         |

## Values and types [#literal]

HashQL's primitive types are `Integer`, `Number`, `String`, `Boolean` and `Null`. Structs and tuples are static collections, with a fixed set of fields or positions that each have their own type. Lists and dictionaries are dynamic collections of any size. Every member of a list shares one element type, and every entry of a dictionary one key type and one value type.

In Draft, you write a value as `2n`, `2.5`, `"two"`, `true` or `null`, and its type as `BigInt`, `Number`, `String`, `Boolean` or `$.prelude().Null`. A `bigint` becomes an `Integer` and a `number` a `Number`, so Draft keeps the distinction HashQL makes.

### Primitive literals [#literals]

Each line is a separate program whose value is its literal. `2` is an `Integer` and `2.5` is a `Number`.

### Structs name their fields [#struct]

A struct has a fixed set of fields, each with a name and its own type. A field can hold another struct. Read a field with [access](#access-struct).

<SideBySide>
<div>

```ts tab="TypeScript" tab-group="hashql-cheatsheet-familiar"

console.log(value);
```

```rust tab="Rust" tab-group="hashql-cheatsheet-familiar"

struct Owner {

    active: bool,

#[derive(Debug)]
#[expect(dead_code, reason = "only the derived Debug output reads the fields")]
struct Value {
    count: i64,

}

    println!("{value:?}");
}
```

print(value)

A HashQL struct's type is its field names and their types, so any struct with the same fields has the same type. Rust compares structs by their declared names instead. Python's nearest equivalent is a dictionary with fixed keys, which nothing checks before the program runs.

### Types describe values [#types]

A struct type gives each field's type, and a tuple type gives each position's type. List and dictionary types take their element types as arguments, as in `List<Integer>`. Here a type describes the input `payload`.

<SideBySide>
<div>

```ts tab="TypeScript" tab-group="hashql-cheatsheet-familiar"
// A type declaration: tsc checks it, and nothing runs.
type Payload = {
  readonly pair: readonly [bigint, string];
  readonly counts: readonly bigint[];
  readonly totals: ReadonlyMap<string, bigint>;
};
```

```rust tab="Rust" tab-group="hashql-cheatsheet-familiar"
use std::collections::BTreeMap;

// [!code focus:7]
// A type declaration: rustc checks it, and nothing runs.
#[expect(dead_code, reason = "the example declares the type and never builds a value")]
struct Payload {
    pair: (i64, String),
    counts: Vec<i64>,
    totals: BTreeMap<String, i64>,
}

fn main() {}
```

```python tab="Python" tab-group="hashql-cheatsheet-familiar"
from typing import TypedDict


# A type declaration for type checkers. Running it prints nothing.
class Payload(TypedDict):
    pair: tuple[int, str]
    counts: list[int]
    totals: dict[str, int]
```

</div>
<div>

```ts tab="TypeScript (Draft)" tab-group="hashql-language"
import { Program } from "@local/hashql";
import * as Draft from "@local/hashql/Draft";
import { Result, pipe } from "effect";

// [!code focus:13]
const { List, Dict } = Program.Prelude.builtin.types;
// BigInt is a type and 2n a value. A record describes a struct and an
// array a tuple, but a list or dictionary needs its type constructor.
// Structural.type returns a Result, which fails for an invalid definition.
const built = pipe(
  Program.Structural.type({
    pair: [BigInt, String],
    counts: List(BigInt),
    totals: Dict(String, BigInt),
  }),
  Result.flatMap((Payload) =>
    Draft.program({ payload: Payload }, (_, { payload }) => payload),
  ),
);

const text = pipe(
  built,
  Result.map(Program.program),
  Result.flatMap(Program.compile),
  Result.getOrThrow,
);
console.log(text);
```

```text tab="Functional notation" tab-group="hashql-language"
(input payload
  (pair: (Integer, String),
   counts: List<Integer>,
   totals: Dict<String, Integer>))
```

```text tab="Reference notation" tab-group="hashql-language"

  pair: (Integer, String),
  counts: List<Integer>,
  totals: Dict<String, Integer>
))
```

```json tab="J-Expr" tab-group="hashql-language"
[
  "::kernel::special_form::input",
  "payload",
  {
    "#struct": {
      "pair": {
        "#tuple": ["::kernel::type::Integer", "::kernel::type::String"]
      },
      "counts": "::kernel::type::List<::kernel::type::Integer>",
      "totals": "::kernel::type::Dict<::kernel::type::String, ::kernel::type::Integer>"
    }
  }
]
```

<Result expected>

With the input `payload` set to `(pair: (2, "two"), counts: [2, 3], totals: {"open": 2})`:

```text

```

</Result>

</div>
</SideBySide>

A type describes values without validating them: a Draft type handle doesn't check caller data at run time. `Structural.type` declares no HashQL type name, unlike [`type`](#type). An input schema also accepts the shorthand directly, as in the [task example](#read-a-task).

## Common program patterns [#control-flow]

Special forms are calls that the compiler treats specially. [More on special forms](/docs/hashql/intro#functional-programming).

### `if` chooses a value [#if]

`if` evaluates a Boolean condition and returns one of two values. [More on `if`](/docs/hashql/intro#choosing-a-value-with-if).

The condition is true, so the expression's value is `2`.

## Put the forms together [#programs]

These programs triage tasks from the [release briefing](/docs/hashql/sdk/typescript/writing-a-query). Each one adds forms to the last, and the final one turns the triage into a rule that reads an input.

### Reuse the rule [#reuse-the-rule]

The triage becomes a closure that captures the status the caller flags, and the program applies it to two tasks. Every run flags `blocked`.

<SideBySide>
<div>

```ts tab="TypeScript" tab-group="hashql-cheatsheet-familiar"
interface Task {
  readonly title: string;
  readonly status: string;
}

const flagged = process.env["FLAGGED"] ?? "";
const summarize = (task: Task) => ({
  title: task.title,
  attention: task.status === flagged ? "review" : "clear",
});

const first = { title: "Confirm the rollout window", status: "blocked" };
const second = { title: "Update the release notes", status: "open" };
console.log([summarize(first), summarize(second)]);
```

```rust tab="Rust" tab-group="hashql-cheatsheet-familiar"
use std::env;

struct Task {
    title: &'static str,
    status: &'static str,
}

#[derive(Debug)]
#[expect(dead_code, reason = "only the derived Debug output reads the fields")]
struct Summary {
    title: &'static str,
    attention: &'static str,
}

fn main() {
    // [!code focus:5]
    let flagged = env::var("FLAGGED").unwrap();
    let summarize = |task: Task| Summary {
        title: task.title,
        attention: if task.status == flagged { "review" } else { "clear" },
    };
    let first = Task { title: "Confirm the rollout window", status: "blocked" };
    let second = Task { title: "Update the release notes", status: "open" };
    // [!code focus:1]
    println!("{:#?}", (summarize(first), summarize(second)));
}
```
