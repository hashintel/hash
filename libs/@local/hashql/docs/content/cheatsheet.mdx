Each section puts a language you know on the left and HashQL on the right. Choose a tab on either side, and the choice follows you down the page. Every tab holds a complete program. The button under it shows the program's result in place:

- **Recorded** results come from running that exact program. A Draft program prints the HashQL program it constructs, as J-Expr. It doesn't evaluate it.
- **Expected** results are what the language specifies. Nothing on this page runs HashQL or queries a graph.

The [introduction](/docs/hashql/intro) explains each form in depth.

## At a glance [#at-a-glance]

| Form                  | Reference notation     | Functional notation   | Draft                                       |
| --------------------- | ---------------------- | --------------------- | ------------------------------------------- |
| [`let`](#let)         | `let x = e in body`    | `(let x e body)`      | `$.let("x", e)`                             |
| [`if`](#if)           | `if c then a else b`   | `(if c a b)`          | `$.if(c, { then, else })`                   |
| [`input`](#input)     | `input(x, T)`          | `(input x T)`         | `Draft.program({ x: T }, ($, inputs) => e)` |
| [`fn`](#fn)           | `(x: T): R -> e`       | `(fn [] {x: T} R e)`  | Not available                               |
| [`use`](#use)         | `use(path, {a: b}, e)` | `(use path {a: b} e)` | `$.import(module, { a: "b" })`              |
| [`access`](#access)   | `e.field`, `e.0`       | ``(`.` e field)``     | `e.field`, `e[0]`                           |
| [`index`](#index)     | `e[i]`                 | `(index e i)`         | `e.$index(i)`                               |
| [`as`](#as)           | `e as T`               | `(as e T)`            | Not available                               |
| [`type`](#type)       | `type T = U in e`      | `(type T U e)`        | `$.type("T", U)`                            |
| [`newtype`](#newtype) | `newtype T = U in e`   | `(newtype T U e)`     | `$.newtype("T", U)`                         |

## `if` chooses a value [#if]

`if` evaluates a Boolean condition and returns one of two values. [More on `if`](/docs/hashql/intro#choosing-a-value-with-if).

## `input` receives a value [#input]

`input` asks the caller for a named, typed value. Each run below supplies `2`, so the expression's value is `2`. [More on `input`](/docs/hashql/intro#receiving-a-value-with-input).

An input is fixed for one execution, and any expression can read it without having it passed down. Environment variables are the nearest host-language equivalent, but they are strings each program parses. A HashQL input declares its type, and the caller supplies a value of that type. Draft declares inputs in the first argument to `Draft.program`. `input(foo, Integer, 2)` would give `foo` a default.

## `use` imports under a local name [#use]

`use` brings a module's items into scope for its body, here `eq` under the name `same`. The expression's value is `true`. [More on `use`](/docs/hashql/intro#bringing-names-into-scope-with-use).

Rust's standard library has no free `eq` function, so the Rust program defines the module it imports from. The host-language imports load code with their own equality rules. ## `access` reads a field or position [#access]

`access` reads a struct field by name or a tuple element by position. Both are fixed in the program, so the compiler checks that they exist. The reference notation writes it as `.`. [More on `access`](/docs/hashql/intro#reading-a-field-with-access).

import * as Draft from "@local/hashql/Draft";
import { Result, pipe } from "effect";

const built = Draft.program({ flagged: String }, ($, { flagged }) => {

      title: "Confirm the rollout window",
      status: "blocked",

    "second",
    Program.Structural.struct({
      title: "Update the release notes",
      status: "open",
    }),

        else: () => $.literal("clear"),
