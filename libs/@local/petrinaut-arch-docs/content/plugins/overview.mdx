A plugin adds buttons, top-bar items, commands, settings and UI to the
Petrinaut editor.
This page names the parts of a plugin and where the editor shows what it adds.
The pages under [Read next](#read-next) cover writing a plugin, the API
tables, and how the editor runs plugins.

![From a manifest to the editor's outlets](@diagrams/plugin-definition.svg)

## The parts

| Part          | What it is                                                                                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Manifest      | Plain data: what the plugin adds and which editor state it reads or changes.                                                                                          |
| Definition    | What `definePetrinautPlugin(manifest)` returns, named `createXPlugin`. It is callable and carries `.manifest`, which User settings reads without running plugin code. |
| Hook          | `useXPlugin(api)`: receives `api` and returns the contributions. A plugin whose contributions need no `api` passes them as an object instead.                         |
| `api`         | What the manifest grants: `errors` and `notifications` always, `settings` when the manifest declares settings, `document` and `experiments` when `access` names them. |
| Contributions | What the hook returns: an entry for each key the manifest declares, plus the optional `root` and `overlay`.                                                           |
| Plugin        | What calling the definition returns. `<Petrinaut plugins>` takes an array of them.                                                                                    |

## Example

```tsx
import { useState } from "react";

import {
  definePetrinautPlugin,
  type PluginHook,
} from "@hashintel/petrinaut/ui";

const createCounterPlugin = definePetrinautPlugin({
  id: "example.counter",
  name: "Counter",
  topBarItems: { counter: { place: "top-bar-end" } },
});

const useCounterPlugin: PluginHook<typeof createCounterPlugin> = () => {
  const [count, setCount] = useState(0);

  return {
    topBarItems: {
      counter: <button onClick={() => setCount(count + 1)}>{count}</button>,
    },
  };
};

export const counterPlugin = createCounterPlugin(useCounterPlugin);

// <Petrinaut handle={handle} plugins={[counterPlugin]} />
```

The manifest declares one top-bar item, `counter`. The hook returns its node
under the same key.

## Where contributions show

- **The top bar**: buttons and top-bar items, at its start or its end.
- **The viewport controls**: buttons, below the canvas's built-in buttons.
- **The command registry**: commands, which a palette the host or another
  plugin renders lists beside the editor's own.
- **Inside the editor**: `root`, for dialogs, overlays and tours.
- **User settings**: the plugin's setting rows, and its row under Plugins,
  where the user switches it off.
