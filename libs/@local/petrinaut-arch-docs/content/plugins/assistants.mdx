The editor's AI assistant comes from a plugin. A plugin whose manifest
declares `assistant: { label }` returns, under `assistant`, a **view**: one
React component that renders the whole assistant UI and draws the assistant
window around its transcript. The editor shows one assistant at a time.

```tsx
import {
  definePetrinautPlugin,
  PetrinautAssistantWindow,
} from "@hashintel/petrinaut/ui";

export const echoPlugin = definePetrinautPlugin({
  id: "example.echo",
  name: "Echo",
  assistant: { label: "Echo" },
})({
  assistant: {
    view: (
      <PetrinautAssistantWindow>
        <EchoTranscript />
      </PetrinautAssistantWindow>
    ),
  },
});
```

The demo site's Petrinaut AI and the AI experiments demo render the website's
[assistant chat](layer:website.plugins.chat) as their view.

## Providing an assistant

| Manifest                      | `api` gains          | The hook returns under `assistant` |
| ----------------------------- | -------------------- | ---------------------------------- |
| `assistant: { label }`        | `assistant.isActive` | `{ view, tabs?, startActions? }`   |
| `assistant: { extends: def }` | `assistant.isActive` | `{ tabs?, startActions? }`         |

| Member         | Type                                    | Notes                                                                                                                                    |
| -------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `view`         | `ReactNode \| null`                     | Rendered once per document while this assistant is shown. `null` until ready: the editor then hides the window and every AI entry point. |
| `tabs`         | `readonly PluginAssistantTab[]`         | Tabs after the chat tab, before the tabs of the plugins extending this assistant.                                                        |
| `startActions` | `readonly PluginAssistantStartAction[]` | Ways to start besides typing. The empty-net prompt offers the first one.                                                                 |

`api.assistant.isActive` is `true` while the editor shows this plugin's
assistant, or the one it extends. A change of `isActive` runs the hook again,
so a plugin can skip work while its assistant is not shown.

## The window

The view draws the window and puts its transcript inside:

```tsx
<PetrinautAssistantWindow
  label? mark? busy? appearance? headerActions? footer? compact? focusTargetRef? focusRequest? onClose?
>
  {transcript}
</PetrinautAssistantWindow>
```

| Prop             | Notes                                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `label`          | The chat tab's label, and the header's title while there are no other tabs. Defaults to the manifest's `assistant.label`. |
| `mark`           | A small mark before the chat tab's label.                                                                                 |
| `busy`           | A turn that ends while another tab is shown marks the chat tab until the chat is shown again.                             |
| `appearance`     | `"default"` or `"pill"`: the tab strip's look.                                                                            |
| `headerActions`  | Buttons in the header, after Float or Dock and before Close.                                                              |
| `footer`         | Shown under every tab, e.g. the composer.                                                                                 |
| `compact`        | `true` shrinks the window to its footer at the editor's bottom right; `"overflow"` lets the footer draw above it.         |
| `focusTargetRef` | Receives focus when the window opens, unless it is disabled or the window is compact.                                     |
| `focusRequest`   | Grows to move focus into the window again.                                                                                |
| `onClose`        | Called when the header's Close button closes the window.                                                                  |

`usePetrinautAssistantWindow()`, called in the view or a tab, returns
`isOpen`, `isChatTabShown`, `compact`, `setCompact`, `close`, `startRequest`
and `consumeStartRequest`. The editor keeps the window's placement, width,
shown tab and start request above the view, so they survive the view
remounting for another document.

The view draws the window, rather than the editor drawing it around the view,
because per-turn state (busy, compact, focus, footer, header actions) then
flows down as props. A window drawn around the view would need those values
passed up and synced through effects.

`PetrinautAssistantWindowPreview` hosts a view outside an editor, with tabs,
for stories and tests. Its `state` prop replaces the open state, compact state
or start request it keeps.

## Tabs and start actions

```ts
interface PluginAssistantTab {
  id: string; // unique among the window's tabs; not "chat"
  label: string;
  mark?: ReactNode;
  activityIdentities?: readonly (number | string)[];
  content: ReactNode;
}
interface PluginAssistantStartAction {
  id: string;
  label: string;
  icon: ReactNode;
}
```

The tabs are the chat tab, then the assistant's tabs, then each extension's.
Ids that appear in a hidden tab's `activityIdentities` badge it; the first list
is the baseline. Each tab renders behind its own boundary and stays mounted
while another tab shows.

The empty-net prompt offers the first start action while its input is empty.
Choosing it opens the window with the start request `{ action: id }`; typing a
prompt there gives `{ text }`. The view reads the request from
`usePetrinautAssistantWindow()` and consumes it.

## Choosing the assistant

- The default is the first running assistant in the list.
- With two or more running, the user picks one under User settings → General →
  AI assistant (stored as `aiAssistantId`), or with the palette commands
  `petrinaut.ai-assistant.use:<id>` ("Use the `<label>` assistant"), one for
  each running assistant that is not shown.
- A stored choice that no running plugin provides falls back to the default
  and is kept for when that plugin returns.

## Extending an assistant

```ts
assistant: { extends: createBrunchPlugin }
```

- The plugin runs only while the plugin it extends runs. When that plugin is
  off, failed or not passed, the extension stays off and User settings shows
  "Needs Brunch".
- It returns `assistant: { tabs?, startActions? }`, added after the extended
  assistant's own while that assistant is shown.
- Matching is by `manifest.id`, so a hot-reloaded definition still matches.
- A plugin extends one assistant. A cycle would need an import cycle, which
  fails when the modules load.

## Failures

A view that throws is replaced by a window saying the assistant stopped
working, and is reported under the plugin's id with place `assistant`. A tab
that throws renders nothing and is reported with place `assistant-tab`. A
plugin whose hook throws leaves the assistant resolution: the plugins that
extend it stop, and the editor shows the next running assistant.

A tab whose id is `"chat"` or another tab's is left out, and reported with
place `assistant-tab` under the id of the plugin that returned it:

- `Petrinaut plugin "<id>" returned an assistant tab with id "<tab>", which is the chat tab's id. Choose another id.`
- `Petrinaut plugin "<id>" returned an assistant tab with id "<tab>", which another tab already has. Choose another id.`
