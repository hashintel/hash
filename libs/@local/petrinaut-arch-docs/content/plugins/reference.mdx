## Manifest

| Key              | Value                                                                                                                                          | Adds to `api`                       | The hook returns |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | ---------------- |
| `id`             | Namespaced, stable and unique among the editor's plugins, such as `example.counter`. Ids starting `petrinaut.` are reserved.                   |                                     |                  |
| `name`           | Titles the plugin's row in User settings → Plugins and the group of its setting rows.                                                          |                                     |                  |
| `description`    | Shown when the plugin's row opens.                                                                                                             |                                     |                  |
| `author`         | Shown beside the name, as in "by HASH".                                                                                                        |                                     |                  |
| `required`       | `true`: the user cannot switch the plugin off, and its row in User settings → Plugins has no switch. A hook that throws still marks it failed. |                                     |                  |
| `access`         | A level per family; see [`access`](#access).                                                                                                   | `document`, `experiments`, `editor` |                  |
| `settings`       | A spec per key; see [Settings](#settings).                                                                                                     | `settings`                          |                  |
| `commands`       | Per key: `{ label, category?, keywords?, shortcut? }`; see [Commands](#commands). Keys contain no dot.                                         |                                     | `commands`       |
| `buttons`        | Per key: `{ label, place, tooltip? }`. `label` is the accessible name; `tooltip` defaults to it.                                               |                                     | `buttons`        |
| `topBarItems`    | Per key: `{ place }`.                                                                                                                          |                                     | `topBarItems`    |
| `readOnlyAction` | `{ label }`: a button on the notice of a blocked edit on a document the host made read-only.                                                   |                                     | `readOnlyAction` |
| `root`           | `true`: the plugin renders UI inside the editor.                                                                                               |                                     | `root`           |
| `assistant`      | `true`: the plugin provides the AI assistant panel.                                                                                            |                                     | `assistant`      |
| `provides`       | `pluginService<T>()`, the type of the service the hook provides.                                                                               |                                     | `provides`       |

Every key but `id` and `name` is optional. Stored settings and the user's
switch are keyed by `id`.

### Places

| `place`             | Takes                     | Where                                                                           |
| ------------------- | ------------------------- | ------------------------------------------------------------------------------- |
| `top-bar-start`     | Buttons and top-bar items | The top bar's left part, after the menu button and before the title.            |
| `top-bar-end`       | Buttons and top-bar items | The top bar's right end, after the built-in buttons.                            |
| `viewport-controls` | Buttons                   | The viewport controls at the canvas's bottom right, below the built-in buttons. |

At each place, each plugin's buttons render before its top-bar items, in the
order of the `plugins` array. Plugin items render before the host's
`slots.topBarStart` and `slots.topBarEnd`, and after its `viewportActions`. The toolbar sets a button's size and variant to
match the built-in buttons.

### Settings

| Field         | Notes                                                                                          |
| ------------- | ---------------------------------------------------------------------------------------------- |
| `type`        | `"boolean"`, shown as a switch, or `"enum"`, shown as a choice.                                |
| `options`     | `"enum"` only: the choices, shown as written.                                                  |
| `default`     | A `boolean`, or one of `options`.                                                              |
| `label`       | The row's title.                                                                               |
| `description` | Optional. A sentence under the label.                                                          |
| `section`     | `"general"` (the default), `"viewport"` or `"labs"`, whose rows carry the Experimental marker. |

### Commands

| Field      | Notes                                                                                   |
| ---------- | --------------------------------------------------------------------------------------- |
| `label`    | What the palette shows.                                                                 |
| `category` | Optional. The palette's grouping; the plugin's `name` by default.                       |
| `keywords` | Optional. Extra search terms beyond the label.                                          |
| `shortcut` | Optional. The chord to display, e.g. `mod+k`. Display only: the registry binds no keys. |

## `access`

```ts
access: {
  document?: "read" | "write";
  experiments?: "read" | "write";
  editor?: "read" | "write";
}
```

| Family        | `"read"` gives                                                                                      | `"write"` also gives                                                   |
| ------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `document`    | `PluginDocumentReader`: `id`, `net`, `title` and `diagnostics` (stores), `extensions`, `diagnose()` | `PluginDocument`: `edit.*` (including `applyAutoLayout`), `setTitle()` |
| `experiments` | `PluginExperimentsReader`: `records`, `optimizationUnavailableReason` (stores)                      | `PluginExperiments`: `run()`                                           |
| `editor`      | `PluginEditorReader`: `navigation` (store)                                                          | `PluginEditor`: `navigate()`, `reveal()`                               |

- **Undeclared means absent.** A family left out of `access` is missing from
  the `api` type and from the object, as is a writer member at `"read"`.
- **Declared does not mean allowed.** Edits are checked when called. Scenario
  and metric edits are refused only on a read-only host. Every other edit,
  `applyAutoLayout` and `setTitle` need Edit mode, no simulation and a
  writable host. Canvas edits follow the same rule in the editor; `setTitle`
  is stricter than the title field, which stays editable in every mode.
  `editor` writes are never refused: the location is not part of the document.
- **Not a security boundary.** Plugins run in the editor's JavaScript realm.

## `api`

| Member                                          | Present              | Notes                                                                                                                            |
| ----------------------------------------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `errors.capture(error, context?)`               | Always               | Sends to the host's error tracker.                                                                                               |
| `notifications.add(input)`                      | Always               | Shows a toast and returns its id.                                                                                                |
| `settings.get(key)`, `settings.set(key, value)` | `settings`           | Typed by the spec. `get` reads the latest stored value. `set` validates, stores and persists, then the hook runs again.          |
| `document`                                      | `access.document`    | See [`api.document`](#apidocument).                                                                                              |
| `experiments`                                   | `access.experiments` | `records` and `optimizationUnavailableReason` are stores. `run(request, options?)` is not refused while the editor is read-only. |
| `editor`                                        | `access.editor`      | See [`api.editor`](#apieditor).                                                                                                  |

`errors.capture` takes `context` as `{ source?, tags? }`, with string, number
or boolean tags. `source` defaults to `plugin.<id>`, and `tags.pluginId` is
always set.

`notifications.add` takes an `AddNotificationInput`: a `message`, and
optionally `detail`, `tone`, `durationMs`, `id` and `action`. A toast still on
screen under the same `id` is not shown again. `action`, `{ label, onClick }`,
adds a button that runs `onClick` and closes the toast.

`run` is the experiment host's `runExperiment(request, { signal, onProgress })`,
described in [AI-created experiments](doc:experiments/ai-created-experiments).

### `api.document`

| Member                   | Level | Notes                                                                                                                                               |
| ------------------------ | ----- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                     | read  | The handle's id. Plugins remount for each document.                                                                                                 |
| `net`                    | read  | `ReadableStore<SDCPN>`: the net without the data of disabled extensions; an empty net until the handle is ready.                                    |
| `title`                  | read  | `ReadableStore<string>`: the title the host passed, or "Untitled" when it passes none.                                                              |
| `extensions`             | read  | The document's `PetrinautExtensionSettings`.                                                                                                        |
| `diagnostics`            | read  | `ReadableStore<DiagnosticsSnapshot>`: the diagnostics the editor shows.                                                                             |
| `diagnose()`             | read  | Checks the current net. Resolves to `PluginDiagnostics`.                                                                                            |
| `edit.<mutation>(input)` | write | One method per core mutation. Edits the root net unless `input.targetSubnetId` is set. Returns an `EditResult`.                                     |
| `edit.applyAutoLayout()` | write | Lays out the viewed subnet in one undo entry, then frames it once drawn. Resolves to `EditResult<ApplyAutoLayoutResult>`.                           |
| `setTitle(title)`        | write | Calls the host's `setTitle`. Refused with `no-title-setter` when the host passed none, and with the read-only reason while the editor is read-only. |

`diagnostics` holds `{ byUri, total, errorCount }`; `byUri` is a `Map` from
document URI to LSP `Diagnostic[]`. `parseDocumentUri(uri)` returns `{ itemType, itemId }`, where
`itemType` is `transition-lambda`, `transition-kernel` or
`differential-equation`. It returns `null` for the URI of an open editor
session, such as a scenario or metric editor, and `total` and `errorCount`
count those sessions too. The store lags `net` by a worker round trip.

`diagnose()` resolves to the diagnostics of the net it checked, and that net
as `net`: `net !== document.net.get()` afterwards means the document changed
meanwhile. It rejects while the language service is starting, just after the
editor mounts.

### `api.editor`

| Member             | Level | Notes                                                                       |
| ------------------ | ----- | --------------------------------------------------------------------------- |
| `navigation`       | read  | `ReadableStore<PetrinautNavigationState>`: where the editor is.             |
| `navigate(update)` | write | Moves the editor: a partial state, or an updater of the current one.        |
| `reveal(target)`   | write | `{ kind: "selection", item }` or `{ kind: "simulateView", mode, itemId? }`. |

`navigation` holds the mode, the edit and Simulate views, the open Simulate
record, the scenario, the subnet, the selection and the overlay, as the host's
navigation sees them. It is set only when one of them changes.

`navigate` is normalized as the host's navigation is: an unknown id, or a
resource of another section, is resolved and never refused. `reveal` selects
`item`, or opens Simulate's `mode` view with the record `itemId` open.

## `EditResult` and refusals

```ts
type EditResult<Value = undefined> =
  { applied: true; value: Value } | { applied: false; reason: EditRefusal };

type EditRefusal = ReadOnlyReason | { kind: "no-title-setter" };
```

| `reason.kind`       | `describeRefusal(reason)` returns                                                          |
| ------------------- | ------------------------------------------------------------------------------------------ |
| `host-readonly`     | This document is read-only; mutations are disabled.                                        |
| `simulate-mode`     | The editor is in simulate mode. Ask the user to switch to edit mode before mutating.       |
| `actual-mode`       | The editor is in actual mode. Ask the user to switch to edit mode before mutating.         |
| `simulation-active` | A simulation is currently `<state>`. Ask the user to reset the simulation before mutating. |
| `no-title-setter`   | The host application does not provide title editing.                                       |

## Contributions

| Key              | Allowed when | Type                                                                                                                                                                                       |
| ---------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `root`           | Declared     | `ReactNode`, rendered inside the editor behind the plugin's error boundary: dialogs, overlays, tours. `null` shows nothing.                                                                |
| `overlay`        | `root`       | Optional `boolean`: `true` while `root` covers the editor. Holds back the empty-canvas assistant prompt.                                                                                   |
| `commands`       | Declared     | Per key: `{ run, when? }`. `when` defaults to `true`; while `false`, the command is not registered.                                                                                        |
| `buttons`        | Declared     | Per key: `{ icon, onClick?, command?, className?, ref? }`. `onClick` runs before `command`, one of the plugin's command keys. A button has at least one of `onClick`, `command` and `ref`. |
| `topBarItems`    | Declared     | Per key: a `ReactNode`.                                                                                                                                                                    |
| `readOnlyAction` | Declared     | `{ run }`: what the read-only notice's button does. The notice shows the action of the first running plugin that declares one, and closes when the button is clicked.                      |
| `assistant`      | Declared     | `{ content, onPrompt? }`: `content` fills the panel behind the plugin's error boundary, and `onPrompt(text)` takes the empty-net prompt's message. The user's choice shows, or the first.  |
| `provides`       | Declared     | The service type `T` of `pluginService<T>()`.                                                                                                                                              |

Every declared key is required and every undeclared one is a type error.
TypeScript also catches a setting value outside an enum's `options`, a button
`command` that is not one of the manifest's command keys, a service of the
wrong type, and a read of a family `access` does not declare.

In the manifest itself, TypeScript catches a key it does not know at any depth,
a reserved id, a command key with a dot, and an enum `default` outside its
`options`. A manifest typed as `PetrinautPluginManifest` is a type error: the
annotation drops the literal keys `api` and the contributions are typed from.
Declare it inline, or with `as const satisfies PetrinautPluginManifest`.

## Exports

From `@hashintel/petrinaut/ui/plugin`. `<Petrinaut>` itself comes from `@hashintel/petrinaut/ui`.

### Definition

- `definePetrinautPlugin(manifest)`: the definition.
  `definePetrinautPlugin(manifest, implementation)`: the plugin.
- `pluginService<T>()`: the type marker for `provides`.

### Types

- Plugins: `PetrinautPlugin`, `PetrinautPluginDefinition`,
  `PetrinautPluginManifest`, `PluginDefinitionRef`, `PluginHook`,
  `PluginImplementation`, `PluginApi`, `PluginContributions`, `PluginService`,
  `ServiceOf`.
- Manifest entries: `PluginSettingSpec`, `PluginSettingSection`,
  `PluginCommandSpec`, `PluginButtonSpec`, `PluginButtonPlace`,
  `PluginTopBarItemSpec`, `PluginTopBarPlace`.
- Contributions: `PluginButton`, `PluginCommand`, `PluginReadOnlyAction`,
  `PluginAssistant`.
- Assistant panel: `AssistantPanel`.
- Access: `PluginAccess`, `AccessApi`, `PluginDocumentReader`,
  `PluginDocument`, `PluginDiagnostics`, `PluginEdits`,
  `PluginExperimentsReader`, `PluginExperiments`, `PluginEditorReader`,
  `PluginEditor`, `PluginErrors`, `PluginNotifications`, `EditResult`,
  `EditRefusal`, `ReadOnlyReason`.
- Editor state: `PetrinautNavigationState`, `PetrinautNavigationUpdate`,
  `SelectionItem`, `PetrinautRevealTarget`, `DiagnosticsSnapshot`,
  `AddNotificationInput`, `ReadableStore`.

### Hooks

- `usePluginService(definition)`: another plugin's service.
- `useStore(store)`, `useStoreSelector(store, selector)`: a store's value in
  render.
- `useCommands()`, `useCommandRegistry()`: the registered commands and the
  registry, for a palette.
- `useCommand(command, options?)`: a command the manifest cannot declare, such
  as one per record. Declared commands need no hook.
- `useAssistantPanel()`: the assistant panel's state, from inside
  `assistant.content`: `isOpen` and `close`.

### Components

- `AssistantPanelTitle`: fills the assistant panel's title bar from inside
  `assistant.content`. `children` render after the assistant icon, such as a
  title or tabs, and `actions` between the dock toggle and the Close button.

### Attributes

- `data-autofocus`: marks the element in `assistant.content` that takes focus
  when the assistant panel opens, such as the composer. Without one, the panel
  takes focus.

### Helpers

- `describeRefusal(reason)`: a sentence for a refusal.
- `pickAssistant(assistants, chosenId)`: the assistant the editor shows among
  `assistants`, anything with a `manifest.id`: the one with `chosenId`, else
  the first. A host passes its assistant plugins less those the user switched
  off, with `assistantPluginId` from `UserSettingsContext`.
- `pluginCommandId(id, key)`: `<plugin id>.<key>`, the id a declared command
  registers under.
- `parseDocumentUri(uri)`: the code document a diagnostics key names, as
  `{ itemType, itemId }`, or `null`.
- `petrinautDocsContent`: the user guide's pages, by name.

## Error messages

| Message                                                                                 | When                                                                                                            |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `Petrinaut plugin "<id>" is passed twice. Pass each plugin once.`                       | Two plugins in `plugins` share an id. Thrown during render.                                                     |
| `Plugin id "<id>" is reserved. ...`                                                     | The id is `petrinaut` or starts with `petrinaut.`. Thrown by `definePetrinautPlugin`.                           |
| `Plugin "<id>" command "<key>" contains a dot. ...`                                     | A command key contains a dot. Thrown by `definePetrinautPlugin`.                                                |
| `Plugin "<id>" setting "<key>" defaults to "<value>", which is not one of its options.` | An enum setting's `default` is outside its `options`, or `options` is empty. Thrown by `definePetrinautPlugin`. |
| `Plugin "<id>" setting "<key>" rejects <value>.`                                        | `settings.set` with an undeclared key or a value its spec rejects. Thrown by `set`.                             |

## Failure reports

A plugin boundary reports what it catches to the host's error tracker with
source `plugin` and tags `{ pluginId, place, contributionId }`:

| `place`                                             | What threw                             | `contributionId` |
| --------------------------------------------------- | -------------------------------------- | ---------------- |
| `hook`                                              | The plugin's hook                      | Not set          |
| `root`                                              | Its `root`                             | Not set          |
| `assistant`                                         | Its `assistant.content`                | Not set          |
| `settings`                                          | Its setting rows                       | Not set          |
| `top-bar-start`, `top-bar-end`, `viewport-controls` | A button or top-bar item at that place | Its key          |
