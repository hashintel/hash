## Running the docs

```bash
yarn workspace @apps/petrinaut-docs dev   # http://localhost:4322
```

One process does everything: `archinaut dev` serves the site shipped with
the tool on the last bundle, reads the annotations, writes `bundle/`, copies
what differs into the site, and rebuilds on every change to a covered package
or to `content/`. A source edit walks only the files it touched and their
dependents, through a compiler kept warm in a worker; a content edit rebuilds
in well under a second. Add `--analysis syntactic` for the cheaper analysis
that follows imports without a type checker.

## Reading without a server

```bash
yarn workspace @local/petrinaut-arch-docs doc:architecture
```

Then open `libs/@local/petrinaut-arch-docs/bundle/architecture.md` for the whole model in one file, or `bundle/diagrams/` for the rendered SVGs.

## Checking annotations

```bash
yarn workspace @local/petrinaut-arch-docs lint:arch-docs
```

Around two seconds, and it needs no `d2`, because it builds the model and reports on it without rendering anything. This is the fastest way to find out whether a declaration you just wrote is valid.

## When a page looks stale

The site serves a copy of the bundle, so three caches sit between an annotation and what the browser shows.

**A page is missing, or Astro reports `UnknownContentCollectionError`.** The synced tree no longer matches the manifest. Re-sync, then restart the dev server:

```bash
turbo run sync:bundle --filter @apps/petrinaut-docs
```

**A page is still wrong after re-syncing.** Astro caches the content collection separately. Remove it and rebuild:

```bash
rm -rf apps/petrinaut-docs/.astro
```

**A component renders in a state your code never produces.** React Refresh keeps component state across hot reloads, so a diagram can hold a value from before your edit. Open a fresh tab before deciding a bug is real.

**Diagrams are missing entirely.** `d2` renders them, and the build only warns when it is absent. Install the repo's tools:

```bash
mise install
```

## Changing what the docs say

The pages under [Architecture](../architecture) are generated. Editing them does nothing, since the next build overwrites the lot. Change the `@layerRoot` and `@role` annotations in the source instead, or the frontmatter of the folder README that declares the layer. See [Declaring layers](doc:maintaining/declaring-layers).

Pages like this one are hand-written and live in `libs/@local/petrinaut-arch-docs/content/`. They are optional: the generator produces a complete bundle with that directory absent.
