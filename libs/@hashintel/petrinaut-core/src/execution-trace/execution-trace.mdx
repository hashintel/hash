An execution trace is the record of one execution of a net as the events
that happened in it, with the state at any position it covers. The layer
owns that record, the two ways to write it and the one player that reads it.
It leaves computing a run to [the event simulation](layer:core.simulation.event-trace)
and reading a host's shapes to [Actual mode](layer:core.actual-mode), which
are two writers of the same trace.

![A simulator's worker and a host's mapping write the same events through a writer. The player and the views read the trace, and never what wrote it.](./execution-trace.d2)

## Entry point

`createExecutionTrace` in `execution-trace.ts` returns a trace and the
writer that fills it. The source keeps the writer. Everything that shows the
execution takes the trace.

## Interface

| Name                 | What a caller takes from it                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------- |
| `ExecutionTrace`     | The events, the state at a position, the coverage, and what a position means                 |
| `TraceWriter`        | `append` events, `cover` a position nothing happened before, `end` the execution             |
| `createTraceEncoder` | Events from markings and firings, for a source without an engine                             |
| `createTracePlayer`  | The viewed position over a trace: play, pause, seek, step, and follow an execution under way |
| `wallClockMsAt`      | The instant of a position, for a trace whose execution happened in real time                 |
| `TraceEvent`         | One record: its position, what fired, and the full state after it                            |

## Protocol

The contract between a source and a reader is the coverage, a store of four
values that `execution-trace.ts` defines:

| Value         | Meaning                                                                           |
| ------------- | --------------------------------------------------------------------------------- |
| `startTime`   | The position of the first event held. The trace says nothing of what came before. |
| `coveredTime` | Every event at or before this position is held. It moves on without an event.     |
| `eventCount`  | Events held, the first state included.                                            |
| `ended`       | The execution is over, and nothing more is appended.                              |

A position is a number of seconds, or of steps when `clock` is `steps`.
`epochMs` is the instant of position 0 on the wall clock, and null for an
execution with no place in real time. `demand(time)` asks the source to
cover a position. A simulator computes up to it, and a host that reports
what happens does nothing.

## Data flow

A host reports that a transition fired:

1. The host's mapping calls `firing` of the encoder with the transitions,
   the tokens taken and the tokens added.
2. The encoder applies them to the marking it keeps and packs the state in
   the frame format a simulator's worker writes.
3. The mapping passes the event to `append` of the writer, and the coverage
   moves to the event's position.
4. A player that follows the trace moves the viewed position to the new
   end, and the views read the state there.

## Rules

- **Coverage never moves back.** A reader would otherwise view a position
  the trace no longer answers. Held by `execution-trace.test.ts`.
- **An event carries the full state after it.** Any event can then be the
  first of a trace, so a trace may join an execution under way and start at
  any position. Held by "starts where its first event is" in
  `execution-trace.test.ts`.
- **The player reads `PlayableTrace` and nothing else of a source.** What
  plays a run plays a host's execution, and the samples of an experiment.
  Held by the type, and by `trace-player.test.ts`, which plays traces a
  test writes.
- **A discrete trace is viewed at its events.** Between two events there is
  nothing the earlier one did not show. Held by `resting-time.test.ts`.
- **The end of a followed execution that is still going is live.** Viewing
  it plays it, and pausing or viewing an earlier position lets go. Held by
  "following an execution that happens on its own" in
  `trace-player.test.ts`.
- **The encoder skips a place or a transition the net does not have.** A
  host's net and its events can be out of step, and the rest of the event
  still shows. Held by `trace-encoder.test.ts`.

## Pitfalls

- A view of a trace that does not start at position 0 is clamped to
  `startTime`, not to 0. Read the start from the coverage.
- `coveredTime` moving does not mean an event arrived. Read `eventCount`
  for that.
- The encoder records no derivatives, so a trace it writes is discrete.
  A host that knows how tokens evolve between firings writes `TraceEvent`s
  itself.
