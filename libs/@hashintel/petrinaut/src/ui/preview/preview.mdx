The preview composes the shared canvas and inspectors into a compact
read-only embed. It is a second root of the package beside `Petrinaut`: it
creates a Core instance of its own and mounts the providers itself, with
fewer of them than the editor. It owns that composition and a compact shell
of a header, a canvas and a properties column. The canvas and the content of
its panels are the editor's.

This page is longer than a guide should be, because the preview repeats a
part of what `PetrinautProvider` and `Petrinaut` compose, and the page says
for each provider whether the preview mounts it.

![PetrinautPreview mounts the document, the location, the presentation profile and the canvas providers, adds the run providers only for a quick simulation, and leaves out the language client, experiments, Monaco, plugins and the editor view.](./preview.d2)

## Entry point

`PetrinautPreview` in `petrinaut-preview.tsx`, published as
`@hashintel/petrinaut/preview` through `src/preview.ts`. It creates a
read-only handle without history over `definition`, an instance over the
handle, and mounts, from the outside in:

1. `ActualModeContext`, only where the host passes `actualMode`.
2. `PortalContainerContext`, whose container is the `OverlayHost` at the end
   of the preview's root.
3. `PetrinautDocumentProvider`, keyed so that a new `definition` remounts
   everything below it.
4. `PetrinautIconProvider`, the icon set of the editor.
5. `PetrinautNavigationProvider`, with the host's controller behind the
   navigation adapter.
6. `PetrinautPresentationProvider` with the profile `preview`.
7. `NotificationsProvider`, `SimulatorsProvider` and `SimulationProvider`,
   only where the host passes `quickSimulation`.
8. `PetrinautCanvasProvider`, keyed by the run settings so that a change of
   step, horizon or speed starts from them.

Below them it renders `SDCPNView`, and around it the parts of the next
section.

## What it leaves out

| Not mounted                                                                                       | Mounted in the editor by   | Why the preview does without                                                                                               |
| ------------------------------------------------------------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `LanguageClientProvider`                                                                          | `PetrinautRuntimeProvider` | It starts the language worker. The preview shows no code, and a quick simulation runs on artifacts compiled at build time. |
| `ExperimentsProvider`, `OptimizationsProvider`, `ExperimentHostProvider`                          | `PetrinautRuntimeProvider` | An embed plays one run and creates no experiment.                                                                          |
| `NotificationsProvider`, `SimulatorsProvider` and `SimulationProvider`, without `quickSimulation` | `PetrinautRuntimeProvider` | A preview that only shows a net starts no simulation worker. The canvas providers read the inert default.                  |
| `MonacoProvider`                                                                                  | `Petrinaut`                | No code editor is shown: `showSourceCode` is off in the `preview` profile.                                                 |
| `PetrinautPluginsProvider`, `CommandRegistryProvider`, `PetrinautSlotsContext`                    | `Petrinaut`                | Plugins, commands and host parts belong to the editor.                                                                     |
| `EditorView`                                                                                      | `Petrinaut`                | The preview has a shell of its own.                                                                                        |

[The React layer](doc:react/react-layer) lists the providers of each group.

## Interface

A host passes `definition`, and at most one of `quickSimulation` and
`actualMode`. They decide the mode the preview opens in: Edit with neither,
Simulate for a quick simulation, Actual for an execution. `navigation` takes
a `PetrinautNavigationController` over `PetrinautPreviewNavigationState`,
which holds the scenario, the component and the selection. The TSDoc of
`PetrinautPreviewProps` has every prop.

`createPreviewNavigationAdapter` in `navigation-adapter.ts` turns the host's
controller into the controller of the full location that
[navigation](doc:react.navigation/navigation) expects. It fills every other
field with its default, holds the mode at the one the props imply, and maps
an update back onto the fields of the preview's state.

## Data flow

A host passes a new `definition`:

1. The host passes its props to `PetrinautPreview`.
2. The preview creates a read-only handle over the definition and an
   instance over the handle, and disposes the instance of the model before.
3. The handle is a new object, which raises a count of models that is part
   of the key of `PetrinautDocumentProvider`. The preview mounts that
   provider afresh, and with it every provider it wraps.
4. A run built from the net before ends with its providers. The location is
   the host's where it passes a controller, and starts from the mode the
   props imply where it passes none.
5. `PetrinautCanvasProvider` publishes the new net to `SDCPNView` and to the
   parts of the editor shell.

## Parts of the editor shell

The preview imports these components from inside the folder of
[the editor shell](layer:ui.views.editor), so a change to one of them is a
change to the preview:

| Component                 | File, under `views/Editor/`                             | Mounted by                                                                  |
| ------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| `SelectedItemProperties`  | `panels/PropertiesPanel/selected-item-properties.tsx`   | `properties-panel.tsx`                                                      |
| `NetNavigationList`       | `panels/LeftSideBar/subviews/nets-list.tsx`             | `preview-net-navigation.tsx`                                                |
| `EventSimulationControls` | `components/BottomBar/event-simulation-controls.tsx`    | `preview-quick-simulation-controls.tsx`                                     |
| `EventTimeline`           | `panels/BottomPanel/subviews/timeline/run-timeline.tsx` | `preview-quick-simulation-controls.tsx`, `preview-actual-mode-timeline.tsx` |

## Rules

- **A borrowed component needs no provider the preview leaves out.** It
  reads contexts the preview mounts, or contexts whose default does nothing.
  What needs Monaco or the language client is
  behind a capability that the `preview` profile switches off in
  `../presentation/presentation-context.ts`. `petrinaut-preview.test.tsx`
  mounts `EventTimeline` below the preview's own providers, in "opens an
  execution in Actual mode on its latest frame, with its timeline", with a
  stand-in for its chart. No test mounts the others there:
  `preview-quick-simulation-controls.test.tsx` replaces
  `EventSimulationControls` and `EventTimeline` with stand-ins, and no
  preview test selects an item or shows a net with components.
- **`quickSimulation` and `actualMode` exclude each other.** The preview
  opens in one mode: Actual for an execution, Simulate for a run. Held by "refuses
  both an execution and Quick Simulation" in `petrinaut-preview.test.tsx`.
- **The adapter keeps only the fields of `PetrinautPreviewNavigationState`.**
  A host of a preview then cannot be sent a mode or an overlay it has no
  place for.
  Held by `navigation-adapter.test.ts`.
- **A quick simulation compiles nothing.** `createPreviewSimulationCompiler`
  answers from the artifacts the host passed, and the preview throws on a
  named scenario that has none. Held by `quick-simulation.test.ts`.

## Pitfalls

- A component of the shell that starts to read the plugin runtime, the
  command registry or an experiment renders in the editor and breaks in the
  preview. The components without a test under the preview's providers show
  it only in an embed.
- The simulation and playback providers read their first configuration once,
  on mount, and the simulators provider its default selection. The preview
  remounts them by a key made of the run settings, and the document
  providers by a key that changes with the model. A new input that is read on
  mount needs to be part of a key.
