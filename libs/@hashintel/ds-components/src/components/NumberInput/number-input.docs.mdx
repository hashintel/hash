## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { NumberInput } from "@hashintel/ds-components";

export const RetryLimitInput = ({
  value,
  onChange,
}: {
  value: number | null;
  onChange: (value: number | null) => void;
}) => (
  <NumberInput
    value={value}
    onChange={onChange}
    min={0}
    max={10}
    width="xs"
    aria-label="Retry limit"
  />
);
```

## Examples

### Basic

NumberInput is controlled: pass `value` and take the parsed number from `onChange`, which reports `null` when the field is empty.

<Stage>
  <NumberInput
    value={32}
    min={1}
    max={512}
    width="xs"
    aria-label="Batch size"
    onChange={noop}
  />
</Stage>

```tsx
import { useState } from "react";

import { NumberInput } from "@hashintel/ds-components";

export const BatchSizeInput = () => {
  const [batchSize, setBatchSize] = useState<number | null>(32);

  return (
    <NumberInput
      value={batchSize}
      onChange={(value) => setBatchSize(value)}
      min={1}
      max={512}
      width="xs"
      aria-label="Batch size"
    />
  );
};
```

### Decimal values

`step` defaults to `1`, which makes an integer input: decimal-separator keys are rejected and parsed values are truncated. A fractional step — or `"any"` — switches to decimal mode and the decimal mobile keyboard.

`min` defaults to `0` — pass a negative `min` to allow negative values. The bounds constrain stepping only: users can still type outside the range, so validate the value and set `invalid` yourself.

```tsx
import { useState } from "react";

import { NumberInput } from "@hashintel/ds-components";

export const EntityCountInput = () => {
  const [count, setCount] = useState<number | null>(1234567);

  return (
    <NumberInput
      value={count}
      onChange={(value) => setCount(value)}
      styledValue={count === null ? null : count.toLocaleString()}
      width="sm"
      aria-label="Entity count"
    />
  );
};
```

### In a form

Inside `Form.Field` the label connects to the input automatically. Keep `invalid` and the `errors` list in step so the message explains the red border.

```tsx
import { Form, NumberInput } from "@hashintel/ds-components";

export const MaxTokensField = ({
  value,
  error,
  onChange,
}: {
  value: number | null;
  error?: string;
  onChange: (value: number | null) => void;
}) => (
  <Form.Field
    label="Max tokens"
    description="Upper limit for each flow step"
    errors={error ? [error] : undefined}
  >
    <NumberInput
      value={value}
      onChange={onChange}
      min={1}
      max={128000}
      width="sm"
      invalid={!!error}
    />
  </Form.Field>
);
```

## Behavior

- The input is controlled only — it never stores its own value. `onChange` reports `number | null`: `null` when the field is empty or unparsable, including after clearing.
- An integer `step` makes an integer input: decimal-separator and exponent keys are blocked with a brief grey flash, and parsed values are truncated. A fractional step (or `"any"`) accepts every locale's decimal separator.
- Typed values are never clamped: arrows and spin buttons stay within `min`/`max`, but typing can leave the range. Validate the value and set `invalid`.
- Scrolling over a focused field doesn't change the value — the wheel is disabled on focus to prevent accidental edits.
- Spin buttons appear on focus and reserve their space while hidden, so the layout never shifts; Firefox never shows them.
- The minimum width fits two digits plus padding — much narrower than other inputs — so number fields sit comfortably in table rows.

## Content

- Name the quantity in the label and put the unit in a suffix adornment: "Memory limit" plus "MB", not "Memory limit in megabytes".
- Use the placeholder for an example value ("e.g. 512"), never as the label — it disappears as soon as users type.
- Put the valid range in the field description, and template errors as "[Field] must be between [min] and [max]": "Batch size must be between 1 and 512."

## Accessibility

NumberInput renders a native `<input type="number">`, which implements the [WAI-ARIA spinbutton pattern](https://www.w3.org/WAI/ARIA/apg/patterns/spinbutton/) — arrow-key stepping and numeric semantics come from the browser.

### What NumberInput provides

- Native spinbutton semantics, arrow-key stepping, and numeric form validation from `<input type="number">`.
- The matching mobile keyboard automatically: numeric for integer steps, decimal otherwise (override with `inputMode`).
- `invalid` sets `aria-invalid`, and inside `Form.Field` the label is associated with the input automatically.
- Wheel protection: scrolling the page can't change a focused field's value.

### What you must do

- Always label the input — via `Form.Field`, your own label with `htmlForId`, or `aria-label`.
- Pair `invalid` with a visible message (for example `Form.Field` `errors`) — color alone doesn't explain the problem.
- Surface the valid range in the label or description — rejected keystrokes and stepping limits only flash the field, they don't announce why.
