## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { Badge, Button } from "@hashintel/ds-components";

export const NotificationsBell = () => (
  <Badge content={3} color="red">
    <Button variant="subtle" iconName="bell" tooltip="Notifications" />
  </Badge>
);
```

### When to use

<DoList

## Examples

### Basic

Wrap the anchor as `children` and pass the badge's own content as `content`. The default badge is grey, round, and overhangs the top-right corner.

<Stage>
  <Badge content={3}>
    <Button variant="subtle">Inbox</Button>
  </Badge>
</Stage>

### Dot

Omit `content` to collapse the badge to a small solid dot — for "something changed" when the count doesn't matter. Dots are always round, no matter what `shape` is set to.

<Stage>
  <Badge color="green">
    <Button variant="subtle" iconName="bell" tooltip="Notifications" />
  </Badge>
  <Badge color="red">
    <Button variant="subtle">Alerts</Button>
  </Badge>
</Stage>

### Capping counts

Numeric content above `max` (default 99) renders as `{max}+`, so stale counts stay honest and short. Strings pass through untouched.

<Stage>
  <Badge content={99} color="blue">
    <Button variant="subtle">Drafts</Button>
  </Badge>
  <Badge content={100} color="blue">
    <Button variant="subtle">Drafts</Button>
  </Badge>
  <Badge content={2400} max={999} color="blue">
    <Button variant="subtle">Drafts</Button>
  </Badge>
</Stage>

### Text and icon content

`content` takes any React node — a short word, an icon, or both. Prefer counts; reserve words for genuinely new things ("New"), and keep them to one word.

<Stage>
  <Badge content="New" color="purple">
    <Button variant="subtle">Flows</Button>
  </Badge>
  <Badge content={<Icon name="check" size="xxs" />} color="green">
    <Button variant="subtle">Sync</Button>
  </Badge>
</Stage>

### Colors

Give each color one meaning per surface — `red` for needs-attention counts, `green` for presence — and keep it consistent.

### Shape

The pill is `round` by default; `square` gives it a small corner radius that sits better against rectangular anchors like tiles and thumbnails.

<Stage>
  <Badge content={5} shape="round" color="blue">
    <Button variant="subtle">round</Button>
  </Badge>
  <Badge content={5} shape="square" color="blue">
    <Button variant="subtle">square</Button>
  </Badge>
</Stage>

### Position

`position` picks the corner the badge overhangs: `top-left`, `top-right` (default), `bottom-left`, `bottom-right`.

<Stage>
  <Badge content={2} color="red" position="top-left">
    <Button variant="subtle" iconName="bell" tooltip="Notifications" />
  </Badge>
  <Badge content={2} color="red" position="top-right">
    <Button variant="subtle" iconName="bell" tooltip="Notifications" />
  </Badge>
  <Badge content={2} color="red" position="bottom-left">
    <Button variant="subtle" iconName="bell" tooltip="Notifications" />
  </Badge>
  <Badge content={2} color="red" position="bottom-right">
    <Button variant="subtle" iconName="bell" tooltip="Notifications" />
  </Badge>
</Stage>

### Circular anchors

A circular anchor's bounding-box corner is empty, so a corner badge floats off the shape (left). Set `alignTo="circle"` to pull it onto the circle's edge (right).

<Stage>
  <Badge content={4} color="red">
    <Button
      shape="round"
      variant="subtle"
      iconName="user"
      tooltip="Assignees"
    />
  </Badge>
  <Badge content={4} color="red" alignTo="circle">
    <Button
      shape="round"
      variant="subtle"
      iconName="user"
      tooltip="Assignees"
    />
  </Badge>
</Stage>

## Behavior

- The badge is centered on its corner, but its inner edge never crosses the anchor's midline — long content like "Processing" grows away from the anchor, not across it.
- The badge ignores pointer events; hovers and clicks land on the anchor beneath it.

## Content

- Keep badge text to a count or one short word — "3", "99+", "New". Longer strings overhang the anchor by at least half their width.
- Cap counts with `max` rather than showing exact large numbers — "99+" reads faster and stays truthful as counts drift.
- Clear the badge (`hide`) once the user has seen what it announces — a badge that never clears stops meaning anything.

## Accessibility

Badge renders no ARIA of its own, so its meaning must live on the anchor.

### What Badge provides

- Plain inline `<span>`s: the pill's text sits in the accessibility tree directly after the anchor, so a screen reader hears "Inbox", then "3".
- Dot badges render no text at all — they are invisible to assistive technology.

### What you must do

- Fold the badge's meaning into the anchor's accessible name — `aria-label="Notifications, 3 unread"` on the anchor explains what a bare "3" can't.
- Never convey state through a dot or its color alone — mirror it in the accessible name ("Alex Leon (online)"), for screen readers and color-blind users.

## Styling

For a fully custom overlay, use `BaseBadge` which positions arbitrary `content` on a corner of `children` and leaves its appearance to you.

```tsx
import { Avatar, BaseBadge, LoadingSpinner } from "@hashintel/ds-components";

export const SyncingIntegration = () => (
  <BaseBadge
    content={<LoadingSpinner size="xxs" />}
    position="bottom-right"
    alignTo="circle"
  >
    <Avatar alt="GitHub integration (syncing)" placeholder={{ icon: "plug" }} />
  </BaseBadge>
);
```
