## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { Toggle } from "@hashintel/ds-components";

export const PublicAccessSetting = () => {
  const [publicAccess, setPublicAccess] = useState(false);

  return (
    <Toggle
      labelOnText="Public access"
      value={publicAccess}
      onChange={setPublicAccess}
    />
  );
};
```

## Examples

### Basic

Toggle is always controlled: `value` holds the on/off boolean and `onChange` receives the next one (see Installation for the state wiring). Apply the change as soon as `onChange` fires — a toggle promises immediate effect.

`offTone` colors the track when the toggle is off. The default `neutral` reads as a plain "off"; `error` flags an off state that needs attention, such as a protection left disabled. Don't signal it with color alone — say why nearby.

### Labels

`labelOnText` renders after the control, on the on side; `labelOffText` renders before it, on the off side. Use either one as the setting's label, or both to caption the two poles — both stay visible whichever way the switch sits.

### In forms

Inside `Form.Field`, leave the label props off — the field's label is wired to the hidden input automatically. When on, the hidden native checkbox submits `"on"` under `name`; `required` blocks native submission while off.

```tsx
import { useState } from "react";

import { Form, Toggle } from "@hashintel/ds-components";

export const InferenceSettingRow = () => {
  const [aiInference, setAiInference] = useState(true);

  return (
    <Form.Field layout="inline" label="Enable AI inference">
      <Toggle
        name="aiInference"
        value={aiInference}
        onChange={setAiInference}
      />
    </Form.Field>
  );
};
```

## Behavior

- The whole component renders as one `<label>` wrapping a hidden native checkbox, so clicking the track or either label toggles. Don't nest it inside another label or interactive element.

## Content

- Label the setting, not the state: "Public access", not "On" or "Enabled". Keep the wording identical whichever way the switch sits.
- Use a short verb or noun phrase — 1–4 words, sentence case, no punctuation: "Autosave", "Sync entity changes".
- In general phrase for the on state: "Show archived entities", rather than "Hide archived entities". Switching off a negative is a double negative.
- Reserve the two-label form for true poles ("Off"/"On"); two named alternatives belong in SegmentedControl.

## Accessibility

Toggle implements the [WAI-ARIA switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/).

### What Toggle provides

- A visually hidden native `<input type="checkbox">` inside a `<label>`.
- `labelOnText`/`labelOffText` render as label parts that name the input.

### What you must do

- Give every toggle a name: `labelOnText`/`labelOffText`, a wrapping `Form.Field` label, or `aria-label` when the visible label lives elsewhere.
- Don't rely on `offTone="error"` color alone — pair it with text that explains the problem.
- Prefer explaining a constraint over `disabled` — a disabled toggle has reduced contrast and doesn't say why it's locked.
