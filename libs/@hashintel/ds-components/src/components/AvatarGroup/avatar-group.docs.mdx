## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { Avatar, AvatarGroup } from "@hashintel/ds-components";

export const EntityContributors = () => (
  <AvatarGroup max={4}>
    <Avatar
      alt="Chris Feijoo"
      src="https://avatars.githubusercontent.com/u/2991143?v=4"
      placeholder={{ initials: "CF" }}
    />
    <Avatar alt="Dele Okafor" placeholder={{ initials: "DO" }} />
    <Avatar alt="Priya Patel" placeholder={{ initials: "PP" }} />
  </AvatarGroup>
);
```

### When to use

<DoList
  items={[
    "Use AvatarGroup to show who's associated with something — an entity's contributors, a flow's participants, a workspace's members — where there's no room for names.",
    <Fragment key="0">
      Use <code>max</code> to keep long collections to a predictable width — the
      badge summarises everyone it hides.
    </Fragment>,
    <Fragment key="1">
      Use <code>total</code> when you fetch only the first page of members, so
      the +N reflects the real count.
    </Fragment>,
  ]}
/>

### When not to use

<DontList
  items={[
    "Don't use a group for a single person — use Avatar on its own.",
    "Don't use it where each person must be identifiable at a glance — given the room, list names next to individual Avatars instead.",
    "Don't use it as a control for choosing people — it only displays membership; use Combobox or Select to pick teammates.",
  ]}
/>

## Anatomy

```tsx
<AvatarGroup>
  <Avatar />
  <Avatar />
  {/* optional — replaces the automatic "+N" badge */}
  <AvatarGroup.More>…</AvatarGroup.More>
</AvatarGroup>
```

### Overflow

Use `max` or `AvatarGroup.More` to handle overflow.

With `max` the +N badge takes the final slot, so `max={4}` renders three avatars plus the badge. When children is not the size of the full set, for example its only the members you've loaded, set `total` to the size of the whole collection.

Or to fully control the overflow, place an `<AvatarGroup.More>` among the children.

## Accessibility

AvatarGroup is a presentational grouping; naming and interaction live on the
Avatars inside it.

### What you must do

- Give every Avatar a real name as `alt` — "Alex Leon", not "avatar" or an ID.
- Give `AvatarGroup.More` an `alt` that states the overflow ("32 more
  members") — only the automatic badge names itself.
- Keep `total` accurate — the badge's +N and its announced name both derive
  from it.

## Styling

- You can customize the size of an avatar with the `--avatar-size` custom property.
  The preset sizes set it for you; `size="custom"` leaves it to you
  (see Sizes above).
- `--avatar-lift-scale` sets how large a hovered avatar grows.
  Override it on the group when a custom size makes the default pop feel off.
