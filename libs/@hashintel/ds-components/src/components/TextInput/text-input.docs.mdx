## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { TextInput } from "@hashintel/ds-components";

export const EntityTypeNameInput = () => {
  const [name, setName] = useState("");

  return (
    <TextInput
      name="entityTypeName"
      placeholder="e.g. Research paper"
      value={name}
      onChange={setName}
    />
  );
};
```

## Examples

### Basic

TextInput is always controlled — `value` and `onChange` are required, and the handler receives the new string first with the raw change event second. `null` and `undefined` values render as empty.

<Stage>
  <TextInput
    width="md"
    placeholder="e.g. Research paper"
    value=""
    onChange={() => {}}
  />
</Stage>

### Input types

Set `type` to match the content so devices show the right keyboard and browsers validate natively; for numbers use NumberInput. Autofill and password managers are blocked by default — set `autocomplete` on fields they should fill, such as sign-in emails and passwords.

<Stage>
  <TextInput
    width="sm"
    type="email"
    placeholder="name@hash.ai"
    value=""
    onChange={() => {}}
    autocomplete
  />
  <TextInput
    width="sm"
    type="password"
    value="correct-horse-battery"
    onChange={() => {}}
    autocomplete
  />
  <TextInput
    width="sm"
    type="url"
    placeholder="https://hash.ai"
    value=""
    onChange={() => {}}
  />
</Stage>

Use `inputMode` when the content is digits but not a number — IDs, one-time codes — to get the numeric keyboard without number-input semantics.

### Disabled

`disabled` greys the field and ignores input. Prefer `readonly` when the user only needs to see the value — disabled styling has poor contrast and suggests the value might become editable.

<Stage>
  <TextInput width="sm" disabled value="Research paper" onChange={() => {}} />
  <TextInput
    width="sm"
    disabled
    placeholder="e.g. Research paper"
    value=""
    onChange={() => {}}
  />
</Stage>

### Invalid

`invalid` turns the border red and sets `aria-invalid`. Pair it with a visible message — Form.Field's `errors` renders and announces one.

<Stage>
  <TextInput
    width="sm"
    invalid
    type="email"
    value="elena@hash"
    onChange={() => {}}
  />
</Stage>

### Loading

Set `loading` while a lookup or save runs — a spinner appears at the end of the field. The input stays editable.

<Stage>
  <TextInput width="sm" loading value="hash.ai/@acme" onChange={() => {}} />
</Stage>

### Read-only

`readonly` strips the field chrome entirely and renders the value as plain text — use it to display stored values alongside editable ones. Unlike `disabled`, the value reads as content, not as a greyed-out control.

<Stage>
  <TextInput width="sm" value="e7f2a49c-3b1d-4e08" onChange={() => {}} />
  <TextInput
    width="sm"
    readonly
    value="e7f2a49c-3b1d-4e08"
    onChange={() => {}}
  />
</Stage>

### Clearable

`clearable` adds a clear button that appears when the field is hovered or focused and a value is present. The default clear empties the input through the normal change pipeline — `onChange` fires with `""` — and keeps focus in the field.

<Stage>
  <TextInput width="sm" clearable value="Person" onChange={() => {}} />
</Stage>

Pass `{ onClear }` to control the reset yourself; `clearable={false}` disables clearing while still reserving the button's space, so the layout doesn't shift when clearability toggles.

### Edit icon

`showEditIcon` adds a pencil at the end of the field to signal that a displayed value is editable. The icon hides while the input is focused.

<Stage>
  <TextInput
    width="sm"
    variant="subtle"
    showEditIcon
    value="Untitled flow"
    onChange={() => {}}
  />
  <TextInput
    width="sm"
    showEditIcon
    value="Research paper"
    onChange={() => {}}
  />
</Stage>

### Variants

`default` draws a bordered field; `subtle` is borderless and reads as inline text until hovered or focused. Use `subtle` for click-to-edit values such as titles and table cells.

<Stage>
  <TextInput width="sm" variant="default" value="Default" onChange={() => {}} />
  <TextInput width="sm" variant="subtle" value="Subtle" onChange={() => {}} />
</Stage>

### Sizes

`md` is the default. Use `sm` and below in dense chrome such as toolbars and table cells, and `lg` for prominent page-level fields; give Form.Field the same `size` so the label scales with the input.

<Stage>

  <TextInput size="md" width="xs" value="md" onChange={() => {}} />

</Stage>

### Widths

The presets (`xs` 6rem, `sm` 15rem, `md` 22.5rem, `lg` 35rem) align stacked inputs without custom CSS; `fullWidth` — the default — fills the container. `fitContent` tracks the value's length as the user types.

### Prefix and suffix

An adornment is an icon (`{ iconName }`), text (`{ text }`), or any node (`{ content }`); adding `onClick` to the first two renders it as a button. Set the adornment's `variant: "subtle"` to drop its background and divider.

<Stage>
  <TextInput
    width="sm"
    prefix={{ iconName: "search" }}
    placeholder="Search entities…"
    value=""
    onChange={() => {}}
  />
  <TextInput
    width="sm"
    prefix={{ text: "https://" }}
    value="hash.ai/@acme"
    onChange={() => {}}
  />
  <TextInput
    width="sm"
    suffix={{ text: "kg" }}
    value="120"
    onChange={() => {}}
  />
</Stage>

### Styled value

`styledValue` renders a formatted view of the value while the input is unfocused; focusing reveals the raw value for editing. Use it to show units, thousands separators or highlighting without corrupting what the user typed.

<Stage>
  <TextInput
    width="sm"
    value="8336817"
    onChange={() => {}}
    styledValue={<strong>8,336,817</strong>}
  />
</Stage>

```tsx
import { useState } from "react";

import { TextInput } from "@hashintel/ds-components";

export const PopulationInput = () => {
  const [population, setPopulation] = useState("8336817");

  return (
    <TextInput
      inputMode="numeric"
      value={population}
      onChange={setPopulation}
      styledValue={population === "" ? "" : Number(population).toLocaleString()}
    />
  );
};
```

### Connected inputs

Set `connectToRightInput` on the left input and `connectToLeftInput` on the right to join a pair into one visual control. Only the `default` variant connects — `subtle` and `readonly` inputs render separately.

## Behavior

- The input is always controlled: `value` feeds the field directly, and `null`/`undefined` render as empty.
- `width` defaults to `fullWidth`; the presets shrink rather than overflow when their container is narrower.
- Browser autofill and password managers are suppressed by default — set `autocomplete` to allow them. Clearable inputs always suppress autofill.
- Clicking anywhere in the field — including text adornments — focuses the input.
- The clear button stays out of the tab order until the field is hovered or focused, and clearing returns focus to the input.
- `autoFocus="never"` marks the input so containers that focus their first input on mount, such as dialogs, skip it.

## Content

- The label names the field and comes from Form.Field; the placeholder shows at most an example value: "e.g. Research paper", "Search entities…".
- Never put requirements in the placeholder — it disappears as the user types. Put format rules in Form.Field's `description`.
- Keep prefix/suffix text to short units and symbols: "https://", "kg", "MB".
- Write error messages as instructions that reuse the label's words: "Enter an entity type name".
- When enforcing `maxLength`, pair the input with CharacterCount so users see the limit before they hit it.

## Accessibility

TextInput renders a native [`<input>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/text) with standard text-editing behavior.

### What TextInput provides

- Inside a Form.Field the input adopts the field's generated id, so the label is associated automatically; `aria-*` props pass through to the `<input>`.
- `invalid` sets `aria-invalid`.
- The clear button is a real `<button>` named "Clear input", reachable with Tab only while visible.

### What you must do

- Always name the input: wrap it in a Form.Field, or pass `aria-label` where a visible label genuinely can't fit — a placeholder is not a label.
- Icon adornment buttons (`{ iconName, onClick }`) carry no accessible name — when the action needs one, pass `{ content }` with your own labelled button.
- Don't signal errors with `invalid` color alone — pair it with a message, e.g. Form.Field's `errors`.
