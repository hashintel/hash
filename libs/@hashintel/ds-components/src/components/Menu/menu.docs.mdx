## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { Button, Menu } from "@hashintel/ds-components";

export const EntityActionsMenu = () => (
  <Menu
    trigger={
      <Button variant="subtle" iconName="chevronDown" iconPosition="right">
        Entity actions
      </Button>
    }
    items={[
      { text: "Edit entity", onClick: () => {} },
      { text: "Duplicate entity", onClick: () => {} },
    ]}
  />
);
```

## Anatomy

Menu is composed of the following parts:

- `trigger` — the element that opens the menu and anchors it: any element
  accepting `aria-expanded`, usually a Button.
- `items` — the menu's content: action (`onClick`), link (`href`), and submenu
  (`subItems`) items, mixed freely with labelled groups and custom rows.
- `header` and `footer` — pinned above and below the items, outside the
  scrollable area, for context or persistent actions.

```tsx
<Menu
  trigger={<Button>Entity actions</Button>} // opens and anchors the menu
  header={<strong>Alice Chen</strong>} // pinned above the items
  items={[
    { text: "Rename", onClick: rename }, // an action
    { text: "View history", href: historyUrl }, // a link
    {
      text: "Move to workspace", // a submenu
      subItems: [{ text: "Acme Corp", onClick: moveEntity }],
    },
    {
      id: "danger",
      label: "Danger", // a labelled group — dividers draw between groups
      items: [{ text: "Delete entity", tone: "error", onClick: confirmDelete }],
    },
  ]}
  footer={<Button variant="link">View all actions</Button>} // pinned below
/>
```

## Examples

### Basic

Every item takes `text` plus exactly one of `onClick`, `href`, or `subItems`.
A plain-string `text` doubles as the item's `id`.

### Icons and descriptions

`icon` reinforces the label, `description` adds one line of secondary text,
and `suffix` renders trailing content such as a count. Don't overuse icons in menus —
icons should differentiate important menu items, not decorate every row.

keys skip them. `loading` adds a spinner — use it while an item's
availability is still being determined.

### Header and footer

`header` and `footer` pin above and below the items, outside the scrollable
area. They come undecorated — add your own divider if the design needs one.
Set `swapHeaderFooterOnFlip` to keep the header on the edge nearest the
trigger when the menu opens upward.

An entry of `{ custom }` renders arbitrary content on its own row. Arrow keys
will skip it — but focusable children inside it stay reachable with Tab.

## Behavior

- The menu's content mounts renders in a portal above the page, preventing most z-index + overflow issues.
- While open, the trigger carries `aria-expanded` and a Button trigger also
  shows its pressed visual.
- Selecting an item closes the menu unless that item sets `keepOpenOnSelect`.
- With an empty `items` array, Menu renders just the trigger with no menu
  behind it; EllipsisMenu disables its trigger instead.
- Arrow keys wrap from the last item to the first (and back) on discrete
  presses, but a held key stops at the boundary instead of cycling.

## Content

- Label the trigger with the scope of the actions — "Entity actions", not
  "Menu" or "Options".
- Write item labels verb-first, 1–3 words, sentence case: "Edit entity",
  "Duplicate", "Copy entity ID". No punctuation.
- Name the object when the menu mixes targets — "Delete property" beats
  "Delete" when nearby items act on the entity. But do not name the object
  when there are no mixed targets as the label then becomes redundant
- Keep `description` to one short clause of consequence or context, not a
  restatement of the label.
- Group labels should be 1–2 word nouns: "View", "Manage".
- Order items by expected frequency of use, and destructive actions last.

## Accessibility

Menu implements the
[WAI-ARIA menu button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/).

### What Menu provides

- The trigger is wired with `aria-haspopup` and `aria-expanded`; closing the
  menu returns focus to it.
- Disabled and loading items are exposed as disabled and skipped by arrow-key
  navigation.
- Item `icon`s are `aria-hidden`

### What you must do

- Make every label carry its full meaning without the icon — icons are not
  announced to screen readers.
- Provide an explicit `id` when `text` is JSX; the id is also what `onClick`
  and `onKeyDown` report.

### Keyboard

| Key                     | Action                                                                                                                                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Tab` / `Shift+Tab`     | When the menu has a focusable `header`, `footer`, or custom row, moves between those rows and the item list. Past either edge the menu closes — `Tab` hands focus to the element after the trigger, `Shift+Tab` to the trigger itself. |
