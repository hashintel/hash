## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { SortMenu } from "@hashintel/ds-components";

export const EntitySort = () => (
  <SortMenu
    items={[
      { name: "Name", sortKey: "name" },
      { name: "Created at", sortKey: "createdAt" },
    ]}
    onChange={(sortKey, direction) => {
      // re-query the collection with the new sort
    }}
  />
);
```

## Examples

### Basic

Pass the sorters as `items` and control the selection with `value`/`onChange`. Selecting a row applies it with its current direction; re-selecting the active sort unchanged just closes the menu.

<Stage>
  <SortMenu
    items={sorters}
    value={{ sortKey: "createdAt", direction: "DESCENDING" }}
  />
</Stage>

### Direction toggling

Hovering or keyboard-highlighting a bidirectional row reveals a direction toggle that applies the flipped direction without closing the menu; the trigger's own direction icon flips the active sort in place. Left/Right arrows on a highlighted row do the same from the keyboard.

<Stage>
  <SortMenu
    items={sorters}
    value={{ sortKey: "name", direction: "ASCENDING" }}
  />
</Stage>

### Direction availability

Each sorter declares `directionsAvailable`: `"both"` (the default), `"ascending"` or `"descending"` for one-way fields, or `"none"` for fields like relevance where direction is meaningless — those rows render no direction icon or toggle.

<Stage>
  <SortMenu
    items={sorters}
    value={{ sortKey: "relevance", direction: "ASCENDING" }}
  />
</Stage>

### Sort icons

`sortIcon` picks the glyph family for a sorter's direction icons: `alphabetical` (the default), `numeric` for counts and scores, and `generic` bars for everything else.

### Custom trigger

Pass a function to render a fully custom trigger; it receives the active sorter and direction. You are then responsible for the trigger's label and accessible name.

```tsx
import { useState } from "react";

import { Button, SortMenu, type SortDirection } from "@hashintel/ds-components";

type SortKey = "name" | "createdAt";

export const EntitySort = () => {
  const [sort, setSort] = useState<{
    sortKey: SortKey;
    direction: SortDirection;
  }>({ sortKey: "name", direction: "ASCENDING" });

  return (
    <SortMenu<SortKey>
      items={[
        { name: "Name", sortKey: "name" },
        { name: "Created at", sortKey: "createdAt" },
      ]}
      value={sort}
      onChange={(sortKey, direction) => setSort({ sortKey, direction })}
      renderTrigger={(sorter, direction) => (
        <Button variant="subtle" iconName="sortDown">
          {sorter ? `Sorted by ${sorter.name}` : "Sort"}
          {direction === "DESCENDING" ? " (desc)" : ""}
        </Button>
      )}
    />
  );
};
```

### Trigger appearance

The trigger is a Button and SortMenu forwards its props: `variant` (default `ghost`), `tone` and `size` (default `sm`). `align="right"` moves the sort glyph to the right of the label.

### Searchable

`searchable` adds a search field above the options — reach for it once a menu passes roughly 10 sorters. The search clears whenever the menu closes.

<Stage>

</Stage>

### Persisting the choice

`saveSortId` writes each change to `localStorage` and restores the saved sort on mount through `onChange` — only while `value` is still `undefined`, so state you restore yourself always wins. A saved sort naming a removed sorter or an unavailable direction is ignored.

```tsx
import { useState } from "react";

import { SortMenu, type SortDirection } from "@hashintel/ds-components";

type SortKey = "name" | "createdAt";

export const EntitySort = () => {
  const [sort, setSort] = useState<
    { sortKey: SortKey; direction: SortDirection } | undefined
  >(undefined);

  return (
    <SortMenu<SortKey>
      items={[
        { name: "Name", sortKey: "name" },
        { name: "Created at", sortKey: "createdAt" },
      ]}
      value={sort}
      onChange={(sortKey, direction) => setSort({ sortKey, direction })}
      saveSortId="entities-table"
    />
  );
};
```

## Behavior

- Selecting a sorter applies its shown direction: the active sort's direction when re-selecting it, otherwise the sorter's first available direction. Re-selecting the active sort unchanged closes without firing `onChange`.
- The trigger reads "Sort" until a value is set; with one it shows the sorter's name, truncating with an ellipsis in narrow containers. The dropdown caps at 300px wide.
- Persistence via `saveSortId` is best-effort: storage errors are swallowed, and the restore runs at most once per mount.

## Content

- Name sorters after the field, 1–3 words in sentence case: "Name", "Created at", "Entity count". The name doubles as the trigger label, so keep it short.
- Give every sorter a distinct name — the search field and accessible names match on it.

## Accessibility

SortMenu implements the [WAI-ARIA menu button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/) through Menu.

### What SortMenu provides

- The trigger's accessible name reads the active sort — "Sort by Name, ascending" — or "Sort" when nothing is selected.
- Direction toggles stay out of the tab order and their labels name the outcome of activating them ("Sort by Name, descending"); Left/Right arrows on the highlighted row are the keyboard equivalent.

### Keyboard

| Key   | Action                                                                         |
| ----- | ------------------------------------------------------------------------------ |
| ← / → | Flip and apply the highlighted sorter's direction (bidirectional sorters only) |

### What you must do

- With a custom `renderTrigger`, provide the trigger's accessible name yourself and keep it in step with the active sort.
- Pick `saveSortId` values unique per collection — saved sorts are keyed by it globally.
