## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { TextArea } from "@hashintel/ds-components";

export const EntityDescriptionField = () => {
  const [description, setDescription] = useState("");

  return (
    <TextArea
      value={description}
      onChange={setDescription}
      placeholder="Describe this entity type…"
      rows={4}
    />
  );
};
```

### Invalid

Set `invalid` when the value fails validation — the border turns red and `aria-invalid` is set. Pair it with a visible error message, such as Form.Field's `errors`.

  <div style={{ width: 360 }}>

### Disabled

Disabled fields keep their value visible but grey out and stop accepting focus. Use `disabled` only while editing is temporarily unavailable — for values the viewer can never edit, prefer `readonly`.

<Stage>
  <div style={{ width: 360 }}>
    <TextArea
      disabled
      value="Synced from GitHub — edit the repository README to change this description."
      onChange={noop}
    />
  </div>
</Stage>

### Read-only

`readonly` drops the field styling entirely and renders the value as plain text, preserving line breaks — the same content without the affordance to edit. Unlike the native `readOnly` attribute, the result is no longer a form control: it isn't focusable and doesn't submit.

<Stage>

### Resizing

`resize` sets which directions the drag handle allows: `vertical` (the default), `horizontal`, `both`, or `none`. Prefer vertical — it lets users make room without disturbing the surrounding layout; use `none` when the layout is fixed.

### Auto-resize

`autoResize` grows and shrinks the field with its content instead of scrolling — right for composer-style inputs. `rows` becomes the minimum height, and manual resizing is disabled.

`characterLimit` renders a counter below the field. The limit is soft: typing past it is never blocked — the counter turns red so the writer can trim, and your validation enforces the limit on submit.

## Behavior

- Clicking anywhere inside the field's box, padding included, focuses the `<textarea>`.
- `characterLimit` never sets the native `maxLength` attribute, so typing and pasting past the limit always work — enforce the limit in validation.

## Content

- Make the placeholder a prompt for the content, sentence case, ending with an ellipsis when it invites typing: "Describe this entity type…".
- Never put the label or requirements in the placeholder — it disappears as soon as the user types. Put requirements in the Form.Field `description`.
- State character limits in the field's description and repeat them in the error: "Description must be 280 characters or fewer."

## Accessibility

TextArea renders a native [`<textarea>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/textarea), which carries the standard text-editing semantics and keyboard behavior.

### What TextArea provides

- Inside a Form.Field it adopts the field's generated id, so the label is associated automatically.
- The character counter announces politely only once the limit is exceeded, instead of narrating every keystroke.

### What you must do

- Label every field: wrap it in a Form.Field, or set `aria-label` when a visible label is impossible — a placeholder is not a label.
- Pair `invalid` with a visible error message, such as Form.Field `errors` — the red border alone doesn't say what's wrong.
- State the character limit in the field's description — until it's exceeded, the counter is visual only.
