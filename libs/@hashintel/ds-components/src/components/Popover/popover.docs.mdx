# Popover

A floating, non-modal panel anchored to a trigger, for lightweight interactive
content.

<ReferenceLinks
  links={[
    { label: "Source", href: meta.links.source, iconName: "code" },
    { label: "Stories", href: meta.links.stories },
  ]}
/>

A popover renders in a portal over the page, so these examples are code-only —
open any [story](https://tokens.hash.design/?path=/story/components-popover--default)
to interact with one.

```tsx
import { useRef, useState } from "react";

import { Button, Popover } from "@hashintel/ds-components";

export const FilterEntitiesButton = () => {
  const triggerRef = useRef<HTMLButtonElement>(null);
  const [open, setOpen] = useState(false);
  const close = () => setOpen(false);

  return (
    <>
      <Button
        ref={triggerRef}
        iconName="filter"
        pressed={open}
        onClick={() => setOpen((wasOpen) => !wasOpen)}
      >
        Filter
      </Button>
      {open ? (
        <Popover triggerRef={triggerRef} onClose={close}>
          <Popover.Container>
            <Popover.Header title="Filter entities" />
            <Popover.Body>Only show entities of type Person.</Popover.Body>
            <Popover.Footer
              secondaryActions={
                <Button size="xs" variant="ghost" onClick={close}>
                  Clear
                </Button>
              }
              actions={
                <Button size="xs" tone="brand" onClick={close}>
                  Apply
                </Button>
              }
            />
          </Popover.Container>
        </Popover>
      ) : null}
    </>
  );
};
```

## Anatomy

```tsx
<Popover triggerRef={triggerRef} onClose={close}>
  <Popover.Container>
    <Popover.Header title="Title" />
    <Popover.Body>Content</Popover.Body>
    <Popover.Footer actions={<Button>Apply</Button>} />
  </Popover.Container>
</Popover>
```

Children are free-form: `Popover.Container` draws the framed panel and accepts
only Header, Body, and Footer, each optional and repeatable — several bodies
render as separate cards. Without `Popover.Container`, children are positioned
as-is and you style the panel yourself.

## Examples

### Opening and closing

There is no `open` prop — render the popover to open it, and remove it from
the tree in `onClose`. Clicks on the trigger never count as outside
interactions, so a toggle trigger like this closes it without immediately
reopening.

```tsx
import { useRef, useState } from "react";

import { Button, Popover } from "@hashintel/ds-components";

export const SavedViewsButton = () => {
  const triggerRef = useRef<HTMLButtonElement>(null);
  const [open, setOpen] = useState(false);

  return (
    <>
      <Button
        ref={triggerRef}
        iconName="eye"
        pressed={open}
        onClick={() => setOpen((wasOpen) => !wasOpen)}
      >
        Saved views
      </Button>
      {open ? (
        <Popover triggerRef={triggerRef} onClose={() => setOpen(false)}>
          <Popover.Container>
            <Popover.Header title="Saved views" />
            <Popover.Body>All entities, People, Recently updated.</Popover.Body>
          </Popover.Container>
        </Popover>
      ) : null}
    </>
  );
};
```

### Custom content

Without `Popover.Container` the popover contributes positioning and dismissal
only — pass any element and style the panel yourself.

```tsx
import { useRef, useState } from "react";

import { Button, Popover } from "@hashintel/ds-components";
import { css } from "@hashintel/ds-helpers/css";

const entityPreview = css({
  backgroundColor: "white",
  borderRadius: "lg",
  boxShadow: "[0 2px 8px rgba(0, 0, 0, 0.15)]",
  padding: "3",
  maxWidth: "[260px]",
  textStyle: "sm",
});

export const EntityPreviewLink = () => {
  const triggerRef = useRef<HTMLButtonElement>(null);
  const [open, setOpen] = useState(false);

  return (

      >

    </>

```

### Header

`Popover.Header` renders `title` as an uppercase label, with `actions` beside
the built-in close button. The close button renders only when the popover has
`onClose`; set `hideCloseButton` when a footer action dismisses it instead.

```tsx
import { useRef, useState } from "react";

import { Button, Popover } from "@hashintel/ds-components";

export const NotificationsButton = () => {
  const triggerRef = useRef<HTMLButtonElement>(null);
  const [open, setOpen] = useState(false);

  return (
    <>
      <Button
        ref={triggerRef}
        iconName="bell"
        onClick={() => setOpen((wasOpen) => !wasOpen)}
      >
        Notifications
      </Button>
      {open ? (
        <Popover triggerRef={triggerRef} onClose={() => setOpen(false)}>
          <Popover.Container>
            <Popover.Header
              title="Notifications"
              actions={
                <Button
                  size="xxs"
                  variant="ghost"
                  iconName="gear"
                  tooltip="Notification settings"
                  autoFocus="never"
                />
              }
            />
            <Popover.Body>
              Mentions, assignments, and completed flow runs.
            </Popover.Body>
          </Popover.Container>
        </Popover>
      ) : null}
    </>
  );
};
```

### Positions

`position` sets the preferred placement: four sides, each with optional
`-start`/`-end` alignment. When it doesn't fit the viewport, the popover flips
to the opposite side.

```tsx
import { useRef, useState } from "react";

import { Button, Popover } from "@hashintel/ds-components";

export const PropertyDetailsButton = () => {
  const triggerRef = useRef<HTMLButtonElement>(null);
  const [open, setOpen] = useState(false);

  return (
    <>
      <Button
        ref={triggerRef}
        variant="subtle"
        iconName="info"
        tooltip="Property details"
        onClick={() => setOpen((wasOpen) => !wasOpen)}
      />
      {open ? (
        <Popover
          triggerRef={triggerRef}
          position="right-start"
          onClose={() => setOpen(false)}
        >
          <Popover.Container>
            <Popover.Header title="Expected values" />
            <Popover.Body>Text, or a list of Text values.</Popover.Body>
          </Popover.Container>
        </Popover>

};
```

### Gap from the trigger

For a trigger anchor, the gap on the placement's axis applies: `gapY` for
`top`/`bottom` placements, `gapX` for `left`/`right`. Both default to 8px.

### Anchoring to a point

`positionFromPoint` anchors to a point relative to the trigger's top-left
corner instead of its edges. The point is re-measured every frame, so the
popover tracks a node while a chart pans or zooms; the cross-axis gap then
offsets the panel across the placement.

```tsx
import { useRef, useState } from "react";

import { Popover } from "@hashintel/ds-components";

type GraphNode = { name: string; x: number; y: number };

export const EntityGraph = () => {
  const canvasRef = useRef<HTMLDivElement>(null);
  const [selectedNode, setSelectedNode] = useState<GraphNode | null>(null);

  return (
    <div ref={canvasRef}>
      {/* Canvas rendering; clicking a node calls setSelectedNode. */}
      {selectedNode ? (
        <Popover
          triggerRef={canvasRef}
          positionFromPoint={{ x: selectedNode.x, y: selectedNode.y }}
          position="right-start"
          onClose={() => setSelectedNode(null)}
        >
          <Popover.Container>
            <Popover.Header title={selectedNode.name} />
            <Popover.Body>Entity details for the selected node.</Popover.Body>
          </Popover.Container>
        </Popover>
      ) : null}
    </div>
  );
};
```

### Initial and return focus

On open the popover focuses its first focusable element, and on close it
returns focus to the trigger. Pass `initialFocusRef` to focus a specific
control instead, and `returnFocusRef` when the trigger will be gone by the
time the popover closes.

```tsx
import { useRef, useState } from "react";

import { Button, Popover, TextInput } from "@hashintel/ds-components";

export const RenameViewButton = () => {
  const triggerRef = useRef<HTMLButtonElement>(null);
  const nameInputRef = useRef<HTMLInputElement>(null);
  const [open, setOpen] = useState(false);
  const [name, setName] = useState("Recently updated");

  return (
    <>
      <Button
        ref={triggerRef}
        iconName="pencil"
        onClick={() => setOpen((wasOpen) => !wasOpen)}
      >
        Rename view
      </Button>
      {open ? (
        <Popover
          triggerRef={triggerRef}
          initialFocusRef={nameInputRef}
          onClose={() => setOpen(false)}
        >
          <Popover.Container>
            <Popover.Header title="Rename view" />
            <Popover.Body>
              <TextInput
                inputRef={nameInputRef}
                value={name}
                onChange={setName}
              />
            </Popover.Body>
          </Popover.Container>
        </Popover>
      ) : null}
    </>
  );
};
```

## Behavior

- Mounting plays the open animation. Dismissals the popover handles (Escape,
  outside clicks, the close button) play the exit animation first and call
  `onClose` when it finishes; buttons you render unmount it immediately via
  your own state.
- Without `onClose` the popover is not dismissable: Escape and outside clicks
  do nothing and the header renders no close button — only unmounting closes
  it.
- Positioning tracks the trigger as it moves, resizes, or scrolls; a point
  anchor is re-measured every frame, so it can follow a node while a chart
  pans or zooms.
- The popover is non-modal: no backdrop, no focus trap, no scroll lock — the
  page behind stays interactive.
- Popovers stack: one opened from inside another layers above it, and
  interacting with the inner one doesn't dismiss the outer.
- A long header `title` wraps around the header `actions` rather than pushing
  them out of the corner.

## Content

- Title the popover with the object or task it shows, 1–3 words — the title
  renders as an uppercase label, so keep it short: "Display options",
  "Filter entities". No punctuation.
- Keep the body to a single task or detail; content that needs sections,
  scrolling, or a multi-step form belongs in a Dialog or Drawer.
- Footer labels follow Button content rules: verb-first, 1–3 words, with the
  confirming action in `actions`.

## Accessibility

Popover wraps [Ark UI's Popover](https://ark-ui.com/docs/components/popover),
rendering the panel as a non-modal `role="dialog"`.

### What Popover provides

- On open, focus moves to the first focusable element inside the panel — the
  built-in close button opts out — or to `initialFocusRef`. On close, it
  returns to the trigger, or to `returnFocusRef`.
- Tabbing past the panel's last element moves focus to the element after the
  trigger, as if the popover were inline after it.
- Escape closes the popover when `onClose` is set; the built-in close button
  is labelled "Close".

### What you must do

- Make the trigger a focusable control, such as a Button holding `triggerRef`
  — the popover renders no trigger of its own, so keyboard access depends on
  yours.
- Provide `onClose` wherever the user should be able to dismiss the popover —
  without it, Escape, outside clicks, and the close button are all disabled.
- Lead the content with text naming its purpose, such as a `Popover.Header`
  title — the panel has no accessible name of its own, so the first content
  read is the user's only context.
- Give header `actions` buttons `autoFocus="never"` so they don't take the
  popover's initial focus.

### Keyboard

Because the trigger lives outside the popover, Tab focus is proxied around it:

| Key                                | Action                                                                  |
| ---------------------------------- | ----------------------------------------------------------------------- |
| `Escape`                           | Close the popover and return focus to the trigger (requires `onClose`). |
| `Tab` from the last element        | Move focus out of the popover, to the element after the trigger.        |
| `Shift+Tab` from the first element | Move focus back to the trigger.                                         |

## Styling

`Popover.Container` draws the panel chrome (surface, radius, shadow) but has
no intrinsic width — set one via `className` when content alone would make an
awkward shape. `className` on the Popover styles the positioned content
element, and `positionerClassName` targets the outer positioner, which carries
the `popover` z-index token — override the layer there.

```tsx
import { css } from "@hashintel/ds-helpers/css";

const filterPanel = css({ width: "[280px]" });

// …
<Popover triggerRef={triggerRef} onClose={close}>
  <Popover.Container className={filterPanel}>
    <Popover.Header title="Filter entities" />
    <Popover.Body>Filter controls.</Popover.Body>
  </Popover.Container>
</Popover>;
```
