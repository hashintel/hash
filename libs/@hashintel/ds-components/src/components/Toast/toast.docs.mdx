## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Mount a `Toaster` once, wrapping the part of the application (usually all
   of it) that shows toasts.

```tsx
import { Toaster } from "@hashintel/ds-components";

export const App = () => <Toaster>{/* …the application… */}</Toaster>;
```

3. Show a toast, in either of two ways.

   Call the `toaster` functions from anywhere — an event handler, a mutation
   callback, code outside React. The toasts they create clean up after
   themselves.

```tsx
import { Button, toaster } from "@hashintel/ds-components";

export const PublishButton = () => (
  <Button
    tone="brand"
    onClick={() =>
      toaster.create({
        tone: "success",
        title: "Entity type published",
        body: "Version 3 is now live.",
      })
    }
  >
    Publish entity type
  </Button>
);
```

   Or render a `Toast` from state, and remove it when `onStatusChange` reports
   `exit` — the same mount-to-open contract as `Dialog`. The other statuses
   (`enter`, plus `behind`/`front` as newer toasts stack in front of it and
   leave again) are informational.

```tsx
import { useState } from "react";

import { Button, Toast } from "@hashintel/ds-components";

export const PublishButton = () => {
  const [published, setPublished] = useState(false);

  return (
    <>
      <Button tone="brand" onClick={() => setPublished(true)}>
        Publish entity type
      </Button>
      {published ? (
        <Toast
          tone="success"

              setPublished(false);
            }
          }}
        >
          <Toast.Title title="Entity type published" />
          <Toast.Body>Version 3 is now live.</Toast.Body>
        </Toast>
      ) : null}
    </>
  );
};
```

<DoList
  items={[
    "Use Toast to report the outcome of a background task — an import, export, or sync — that finished while the user was doing something else.",
    "Use Toast to surface async errors and results, so that the information isn't lost once the user has moved on. Offer a retry action where one makes sense.",
  ]}

### When not to use

<DontList
  items={[
    "Don't put information the user must act on in a toast — it disappears. Use Dialog to force a decision.",
    "Don't toast validation errors next to a form — show them at the field.",

## Anatomy

```tsx
// Props API
const id = toaster.create({
  tone: "error",
  variant: "soft",
  position: "bottom-end",
  title: "Import failed",
  body: "The file exceeds the 10 MB limit.",
  actions: <Toast.Action>Retry</Toast.Action>,
});

// JSX API
toaster.create(
  <Toast tone="error" variant="soft" position="bottom-end">
    <Toast.Title title="Import failed" />
    <Toast.Body>The file exceeds the 10 MB limit.</Toast.Body>
    <Toast.Actions actions={<Toast.Action>Retry</Toast.Action>} />
  </Toast>,
);

toaster.update(id, { body: "The file exceeds the 20 MB limit." });

toaster.close(id);
```

The props API maps `title`, `body`, and `actions` onto the standard parts;
use the JSX API for custom content.

## Examples

### Tones and variants

`tone` and `variant` reuse Banner's visual system: `solid` fills with the
saturated tone color, `soft` tints the surface, and `outline` draws a border
on a page-colored card. Each tone also sets `Toast.Title`'s default icon.

export const tonesCode = `<Toast tone="success" variant="soft">
  <Toast.Title title="A success soft toast" />
  <Toast.Body>Describe what happened in a sentence.</Toast.Body>
</Toast>`;

export const TonesDemo = () => {
  const [queued, setQueued] = useState([]);
  const fire = (tone, variant) =>
    setQueued((previous) => [...previous, { key: Date.now(), tone, variant }]);
  return (
    <Toaster>
      {["neutral", "brand", "success", "warning", "error"].map((tone) =>
        ["soft", "outline", "solid"].map((variant) => (
          <Button key={`${tone}-${variant}`} size="xs" onClick={() => fire(tone, variant)}>
            {tone} {variant}
          </Button>
        )),
      )}
      {queued.map(({ key, tone, variant }) => (
        <Toast
          key={key}
          tone={tone}
          variant={variant}
          onStatusChange={({ status }) => {
            if (status === "exit") {
              setQueued((previous) => previous.filter((toast) => toast.key !== key));
            }
          }}
        >
          <Toast.Title title={`A ${tone} ${variant} toast`} />
          <Toast.Body>Describe what happened in a sentence.</Toast.Body>
        </Toast>
      ))}
    </Toaster>
  );
};

### Actions

Fill `Toast.Actions` with `Toast.Action` buttons, and pass
`duration={Infinity}` so the toast stays until the user responds.

`closeToast` dismisses the toast on click; if `onClick` returns a promise, the
button shows a spinner and the toast stays open until it resolves.

export const actionsCode = `<Toast tone="error" duration={Infinity}>
  <Toast.Title title="Import failed" />
  <Toast.Body>The file exceeds the 10 MB limit.</Toast.Body>
  <Toast.Actions
    actions={
      <>
        {/* A returned promise defers the close until the retry finishes. */}
        <Toast.Action closeToast onClick={() => retryImport()}>
          Retry
        </Toast.Action>
        <Toast.Action>Details</Toast.Action>
      </>
    }
  />
</Toast>`;

export const ActionsDemo = () => {
  const [visible, setVisible] = useState(false);
  return (
    <Toaster>
      <Button onClick={() => setVisible(true)}>Import file</Button>
      {visible ? (
        <Toast
          tone="error"
          duration={Infinity}
          onStatusChange={({ status }) => {
            if (status === "exit") {
              setVisible(false);
            }

          <Toast.Title title="Import failed" />
          <Toast.Body>The file exceeds the 10 MB limit.</Toast.Body>

### Custom content

`withPadding={false}` for an edge-to-edge layout. The function form receives

### Duration and dismissal

`success` toasts dismiss sooner than other tones; `duration` (in milliseconds,
or `Infinity`) overrides it. Hovering, focusing, or leaving the page pauses
the timers. `shouldCloseOn="none"` removes the close button and Escape.

export const durationCode = `<Toast duration={30000}>
  <Toast.Title title="Long-lived toast" />
  <Toast.Body>Stays for 30 seconds.</Toast.Body>
</Toast>

<Toast shouldCloseOn="none" duration={4000}>
  <Toast.Body>No close button; gone after 4 seconds.</Toast.Body>
</Toast>`;

export const DurationDemo = () => {
  const [queued, setQueued] = useState([]);
  const fire = (extras) =>
    setQueued((previous) => [...previous, { key: Date.now(), ...extras }]);
  return (
    <Toaster>
      <Button onClick={() => fire({ duration: 30000, label: "Stays for 30 seconds." })}>
        Show for 30s
      </Button>
      <Button
        onClick={() =>
          fire({
            duration: 4000,
            shouldCloseOn: "none",
            label: "No close button; gone after 4 seconds.",
          })
        }
      >
        No close button
      </Button>
      {queued.map(({ key, label, ...extras }) => (
        <Toast
          key={key}
          {...extras}
          onStatusChange={({ status }) => {
            if (status === "exit") {
              setQueued((previous) => previous.filter((toast) => toast.key !== key));
            }
          }}
        >
          <Toast.Body>{label}</Toast.Body>
        </Toast>
      ))}
    </Toaster>
  );
};

### Position

`position` picks the viewport edge or corner the toast stacks at; toasts
sharing a position share a stacking region. `left`/`right` values map onto
the nearest corner (`-start` the top one, `-end` the bottom one). The
centered `top` and `bottom` placements render slightly wider by default.

export const positionCode = `<Toast position="top">
  <Toast.Body>Placed top.</Toast.Body>
</Toast>`;

export const PositionDemo = () => {
  const [queued, setQueued] = useState([]);
  const fire = (position) =>
    setQueued((previous) => [...previous, { key: Date.now(), position }]);
  return (
    <Toaster>
      {["top-start", "top", "top-end", "bottom-start", "bottom", "bottom-end"].map(
        (position) => (
          <Button key={position} size="xs" onClick={() => fire(position)}>
            {position}
          </Button>
        ),
      )}
      {queued.map(({ key, position }) => (
        <Toast
          key={key}
          position={position}
          tone="brand"
          onStatusChange={({ status }) => {
            if (status === "exit") {
              setQueued((previous) => previous.filter((toast) => toast.key !== key));
            }
          }}
        >
          <Toast.Body>Placed {position}.</Toast.Body>
        </Toast>
      ))}
    </Toaster>
  );
};

## Content

- Lead with the outcome in the title, in a few words: "Entity type
  published", "Import failed".
- Use `Toast.Body` only when more detail is necessary. For example what changed, or what to
  do about a failure.
- Name action buttons with a verb ("Undo", "Retry", "View").

## Accessibility

Toasts follow the
[WAI-ARIA alert pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alert/).

### What Toast provides

- Each stacking region is a labelled `role="region"` landmark with
  `aria-live="polite"`, so new toasts are announced without interrupting what
  the screen reader is currently saying.
- Each toast is a `role="status"` element labelled by its title and described
  by its body.
- The hotkey <Kbd keys="alt+t" /> moves focus into a region; toasts
  are focusable, and <Kbd keys="escape" /> dismisses the focused one (unless
  `shouldCloseOn="none"`).
- Timers pause while the pointer or focus is inside a region and while the
  page is idle — the tab hidden or the window unfocused — so a toast can't
  vanish mid-read.

### What you must do

- Keep toasts supplementary: anything the user must read or act on belongs in
  persistent UI, since a toast may never be noticed.
- Don't rely on color alone to distinguish outcomes — the title should carry
  the meaning ("Import failed", not just a red tint).
- If not using the functional api, remove the `Toast` element when `onStatusChange` reports `exit`;
  otherwise the next render of a stale element re-creates the toast.

### toaster

The imperative counterpart to rendering `Toast` elements; it requires a
mounted `Toaster` and its toasts clean up after themselves.

- `toaster.create(props | element)` — shows a toast and returns its id; an
  input carrying the id of a showing toast replaces it in place.
- `toaster.promise(promise, { loading, success, error })` — shows the
  persistent `loading` toast, then replaces it with `success` or `error` —
  toned accordingly by default — when the promise settles. Returns the input
  promise. The props form's `loading` defaults to `true` there, showing a
  spinner in the title's icon slot; a `Toast` element passed as `loading` must
  add its own with `<Toast.Title loading />`.
- `toaster.update(id, props)` — merges new props into a showing toast.
- `toaster.close(id)` — dismisses a showing toast, including declaratively
  rendered ones, by id.
