## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { Button, Dialog } from "@hashintel/ds-components";

export const InviteTeammateButton = () => {
  const [open, setOpen] = useState(false);

  return (
    <>
      <Button tone="brand" onClick={() => setOpen(true)}>
        Invite teammate
      </Button>
      {open ? (
        <Dialog size="sm" onClose={() => setOpen(false)}>
          <Dialog.Header title="Invite teammate" />
          <Dialog.Body>
            <p>Enter the email address of the person to invite.</p>
          </Dialog.Body>
        </Dialog>
      ) : null}
    </>
  );
};
```

## Anatomy

```tsx
<Dialog onClose={onClose}>
  <Dialog.Header
    title="Title"
    description="One line of context"
    iconName="gear"
    actions={headerActions}
  />
  <Dialog.Body>Content</Dialog.Body>
  <Dialog.Footer actions={primaryActions} secondaryActions={startActions} />
</Dialog>
```

`Dialog.Body` is required; `Dialog.Header` and `Dialog.Footer` are optional, and the types enforce the header–body–footer order. A close button renders automatically — inside the header, or alone when there is no header — unless `shouldCloseOn="none"`.

### Initial and return focus

By default, focus moves to the first focusable element that hasn't opted out via `autoFocus="never"`, and returns to the trigger on close. Point `initialFocusRef` at the element the task starts with — the Cancel button for destructive confirmations — and `returnFocusRef` wherever focus should land if the trigger is gone.

## Behavior

- While a dialog is open the page behind it can't scroll. The header and footer stay pinned, and scroll applies just to the dialog body.
- Mounting a second dialog while one is open stacks it. Try to keep stacks no more than two deep — deeper nesting disorients users.

## Content

- Write titles verb-first, 1–4 words, sentence case: "Edit workspace", "Delete entity type". No terminal punctuation.
- Match the primary action's label to the title's verb — "Delete property" under a "Delete property" title, never "OK" or "Yes".
- "Cancel" is the established dismiss label; prefer it to "Close" whenever the dialog edits anything.
- Keep the header description to one sentence of context or consequence: "Scheduled runs stop while the flow is archived."
- For destructive actions, state what is affected and how many things in the body — "removed from 3 entity types".

## Accessibility

Dialog implements the [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

### What Dialog provides

- Renders `role="dialog"` with focus trapped inside; while open, the rest of the page is hidden from assistive technology and page scroll is locked.
- Wires the header's `title` and `description` to `aria-labelledby` and `aria-describedby` automatically.
- Moves focus on open to `initialFocusRef`, else the first element with `autoFocus`, else the first focusable element not marked `autoFocus="never"` (the built-in close button opts out). On close, focus returns to the trigger, or to `returnFocusRef` when set.
- Labels the built-in close button "Close dialog", and `loading` sets `aria-busy` with a polite live region over the body.

### What you must do

- Give every dialog with a header a `title`; when it has none, pass `aria-label` naming the task.
- With `shouldCloseOn="none"`, Escape is disabled — a deviation from the APG pattern — so always render a visible, enabled action that closes the dialog.
- Give header `actions` buttons `autoFocus="never"` so initial focus starts on the task, not the chrome.
