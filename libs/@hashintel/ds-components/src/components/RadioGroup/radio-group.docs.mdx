## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { RadioGroup } from "@hashintel/ds-components";

export const EntityVisibility = () => {
  const [visibility, setVisibility] = useState<
    "private" | "workspace" | "public"
  >("workspace");

  return (
    <RadioGroup
      aria-label="Entity visibility"
      items={[
        { value: "private", label: "Only me" },
        { value: "workspace", label: "Everyone in the workspace" },
        { value: "public", label: "Anyone with the link" },
      ]}
      value={visibility}
      onChange={setVisibility}
    />
  );
};
```

## Examples

### Basic

RadioGroup is controlled: `value` holds the selected option's value and `onChange` receives the newly selected one. Each item takes a unique `value` plus any Radio props, such as `label`, `disabled`, or `tone`.

## Behavior

- `onFocus` and `onBlur` fire only when focus enters or leaves the group as a whole — moving between options doesn't retrigger them.
- Options share one `name` for form submission, auto-generated unless you pass one.
- Users can move the selection but never clear it — `onChange` always receives an option value.
- `required` sets `aria-required` on the group but doesn't enable native form validation — validate on submit and set `invalid`.

## Content

- Write option labels as short, parallel phrases — sentence case, under 4 words, no end punctuation: "Hourly", "On entity update".
- Make options mutually exclusive and cover every case — add an explicit "Other" or "No preference" option rather than forcing a wrong fit.
- Order options logically — by likely frequency of use, or smallest to largest; alphabetically when there's no natural order.
- Let long labels wrap rather than truncating them — the circle stays aligned with the first line.

## Accessibility

Options are native radio inputs; together they implement the [WAI-ARIA radio group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/).

### What RadioGroup provides

- Renders a `role="radiogroup"` container, with `aria-required` when a selection is required and `aria-orientation` matching the layout.

### What you must do

- Always name the group: a visible label via `Form.Field` with `as="legend"`, or `aria-label` when the surrounding context already says what the choice is.
- Pair `invalid` with an error message, e.g. `Form.Field`'s `errors` — the red styling alone isn't perceivable by everyone.
- Explain disabled options in nearby text — a disabled radio doesn't say why it's unusable.
