## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { Form, TextInput } from "@hashintel/ds-components";

export const EntityNameField = () => {
  const [name, setName] = useState("");

  return (
    <Form.Field label="Entity name" required>
      <TextInput name="entityName" value={name} onChange={setName} required />
    </Form.Field>
  );
};
```

### When not to use

<DontList
  items={[
    <>
      Don't put two inputs in one Form.Field — it labels exactly one control.

    </>,
    <>
      Don't use a placeholder instead of a label — it disappears as soon as a

## Anatomy

`Form.Field` renders its label, description and error parts from props; you only compose the structural parts.

```tsx
<Form.Section>
  <Form.Field
    label="Name" // renders Form.Field.Label
    description="Helper text" // renders Form.Field.Description
    errors={["Error message"]} // renders Form.Field.Errors
  >
    {/* exactly one input */}
  </Form.Field>

  <Form.Row>
    <Form.Field label="Minimum">{/* input */}</Form.Field>
    <Form.Field label="Maximum">{/* input */}</Form.Field>
  </Form.Row>
</Form.Section>
```

## Examples

### Basic

A field needs only a `label` and a single input child — the label is associated with the input automatically, no ids required.

      onChange={() => {}}
    />
  </Form.Field>

### Required

`required` adds the mark to the label only — it never reaches the input. Set `required` on the input too so forms and assistive technology enforce it.

<Stage>

      type="email"
      width="md"
      value="elena@hash.ai"
      onChange={() => {}}
      required
    />
  </Form.Field>
</Stage>

`disabled` greys the field's label, description and errors; disable the input separately — the prop doesn't cascade.

Every field needs a label. When the context makes a visible one redundant — a lone search input, a table cell — set `hideLabel` so it stays announced to screen readers.

`layout="inline"` places the label and input on one line — the settings-panel arrangement. `inputAlign="end"` pushes the input to the far edge of the row.

### Label direction

`labelDirection="right"` puts the label after the input in inline layout — the trailing-label pattern. In block layout it right-aligns the label, description and errors instead.

### Grouping related inputs

A `<label>` can name only one control. When the field wraps a group — RadioGroup, CheckboxGroup — set `as="legend"` so the whole group is named with fieldset semantics.

<Stage>

    label="Entity visibility"
    description="Who can see entities created by this flow."
  >
    <RadioGroup
      name="visibility"
      items={[
        { value: "private", label: "Only me" },
        { value: "workspace", label: "Everyone in the workspace" },
        { value: "public", label: "Public" },
      ]}
      value="workspace"
      onChange={() => {}}
    />
  </Form.Field>
</Stage>

### Rows

`Form.Row` places fields side by side, sharing the row's width and bottom-aligned so inputs line up; `gap` controls the spacing. For a message that belongs to the pair rather than one field, pass a `Form.Field.Errors` element to `errors` — it renders below the whole row.

### Custom inputs

Every ds-components input picks up the field's generated id automatically. A hand-rolled input must read `useFieldId` and set it as its `id`, or the label points at nothing.

```tsx
import { useState } from "react";

import { Form, useFieldId } from "@hashintel/ds-components";

const ColorInput = ({
  value,
  onChange,
}: {
  value: string;
  onChange: (value: string) => void;
}) => {
  const id = useFieldId();
  return (
    <input
      type="color"
      id={id ?? undefined}
      value={value}
      onChange={(event) => onChange(event.target.value)}
    />
  );
};

export const AccentColorField = () => {
  const [color, setColor] = useState("#0775e3");

  return (
    <Form.Field label="Accent color">
      <ColorInput value={color} onChange={setColor} />
    </Form.Field>
  );
};
```

### Form libraries

`Form.Field` is driven entirely by props, so it drops into any form library. With TanStack Form, bind the label and errors once in a shared field component; in a real app the contexts and field components live in one module that every form imports.

```tsx
import { createFormHook, createFormHookContexts } from "@tanstack/react-form";

import { Form, TextInput } from "@hashintel/ds-components";

const { fieldContext, formContext, useFieldContext } = createFormHookContexts();

const TextField = ({
  label,
  required,
}: {
  label: string;
  required?: boolean;
}) => {
  const field = useFieldContext<string>();

  return (
    <Form.Field
      label={label}
      required={required}
      errors={field.state.meta.errors}
    >
      <TextInput
        name={field.name}
        value={field.state.value}
        onChange={(value) => field.handleChange(value)}
        onBlur={field.handleBlur}
        required={required}
        invalid={field.state.meta.errors.length > 0}
      />
    </Form.Field>
  );
};

const { useAppForm } = createFormHook({
  fieldComponents: { TextField },
  formComponents: {},
  fieldContext,
  formContext,
});

export const InviteTeammateForm = () => {
  const form = useAppForm({
    defaultValues: { email: "" },
    onSubmit: ({ value }) => console.log(value),
  });

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        void form.handleSubmit();
      }}
    >
      <form.AppField
        name="email"
        validators={{
          onChange: ({ value }) =>
            /^\S+@\S+\.\S+$/.test(value)
              ? undefined
              : "Enter a valid email address",
        }}
      >
        {(field) => <field.TextField label="Teammate email" required />}
      </form.AppField>
    </form>
  );
};
```

## Behavior

- Nothing is injected into children: the field talks to its input only through the generated label id. Set `size`, `disabled`, `required` and `invalid` on the input yourself.
- With `as="legend"` the generated id is not provided to children — group inputs label their own options.
- Inline fields placed directly inside a `Form.Section` dissolve their own box and align onto the section's shared columns; a column no field uses collapses to zero width.
- `Form.Section` spaces adjacent fields automatically; any other child (headings, paragraphs, `Form.Row`) spans the full section width and manages its own vertical spacing.
- `Form.Row` stretches children equally and strips their margins; rows wrap when space runs out unless `noWrap` is set.
- `inputAlign` is logical: with `labelDirection="right"` the row mirrors, so `inputAlign="end"` lands on the left edge.
- `Errors` renders one message inline and several as a list; an empty array renders nothing.

## Content

- Labels name the data, 1–3 words, sentence case, no trailing punctuation: "Entity type name", "Teammate email".
- Division of labor: the label names the field, the description carries format or consequence ("You can't change this later."), the placeholder shows at most an example value — never requirements, which vanish once the user types.
- Write errors as instructions that reuse the label's words: "Enter an entity type name", "Maximum must be at least the minimum". Avoid "please", "sorry" and the word "invalid".
- Mark required fields consistently: if one required field carries the mark, they all should.

## Accessibility

Form fields build on native `<fieldset>`, `<label>` and `<legend>` semantics — see the [WAI forms tutorial](https://www.w3.org/WAI/tutorials/forms/) for the underlying model.

### What Form provides

- `Form.Field` renders a real `<fieldset>` and wires its `<label>` to the input through a generated id every ds-components input adopts automatically.
- `as="legend"` names the whole group, keeping the required mark and tooltip out of the group's accessible name.
- `hideLabel` hides the label visually but keeps it announced.
- Error messages render with `role="alert"`, so they're announced when they appear.
- The tooltip trigger and label actions sit outside the `<label>` element, so they don't leak into the input's accessible name and clicking them doesn't focus the input.

### What you must do

- Always pass a `label` — use `hideLabel` rather than leaving it empty or relying on a placeholder.
- Set `as="legend"` when the field wraps more than one input (RadioGroup, CheckboxGroup) — a label can name only one control.
- Mirror field state on the input: `invalid` when passing `errors`, and `disabled`/`required` on both.
- Give custom inputs the `useFieldId` id (see [Custom inputs](#custom-inputs)); without it the label is not associated.
