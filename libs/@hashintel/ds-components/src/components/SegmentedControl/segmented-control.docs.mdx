## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { SegmentedControl } from "@hashintel/ds-components";

export const RunHistoryRange = () => {
  const [range, setRange] = useState("7d");

  return (
    <SegmentedControl
      aria-label="Time range"
      value={range}
      onChange={setRange}
      items={[
        { label: "24h", value: "24h" },
        { label: "7d", value: "7d" },
        { label: "30d", value: "30d" },
      ]}
    />
  );
};
```

## Examples

### Basic

The control is always controlled: pass the selected `value` and update it from
`onChange` — there is no internal state or `defaultValue`. Each item pairs a
visible `label` with the `value` your state stores.

    aria-label="Entity view"
    value="table"
    onChange={() => {}}
    items={[
      { label: "Table", value: "table" },

</Stage>

### Disabled

Set `disabled` on the control to lock the whole choice, or on one item to
remove a single option while the rest stay selectable. When you must disable a

### Icon-only segments

Omit `label` to render an icon alone — right for tight toolbars. Every
icon-only segment needs a `tooltip`: it names the option on hover and focus,
and doubles as its accessible label.

### Tooltips

Any segment can take a `tooltip` for context beyond its label, with
`tooltipOptions` adjusting placement and timing. Tooltips open on hover and
keyboard focus after a slow delay, and stay open while arrow keys move the
selection.

### In forms

Each segment renders a hidden radio input, so with `name` the selected value
submits with a plain form. Wrap the control in `Form.Field` for a visible label
that's associated automatically.

```tsx
import { useState } from "react";

import { Form, SegmentedControl } from "@hashintel/ds-components";

export const VisibilityField = () => {
  const [visibility, setVisibility] = useState("workspace");

  return (
    <Form.Field label="Visibility">
      <SegmentedControl
        name="visibility"
        value={visibility}
        onChange={setVisibility}
        items={[
          { label: "Private", value: "private" },
          { label: "Workspace", value: "workspace" },
          { label: "Public", value: "public" },
        ]}
      />
    </Form.Field>
  );
};
```

## Behavior

- The control is `width: fit-content` by default. Widen it via `className` and
  segments share the extra space equally; constrain it and labels ellipsize
  while icon-only segments stay square.
- There is no deselection: `onChange` only ever fires with a segment's value,
  so clicking the selected segment never empties the choice.

## Content

- Name the resulting view or option with nouns, 1–2 words: "Table", "Graph",
  "30d". Segments show state — they don't perform actions.
- Keep labels similar lengths so segments read as equal peers — one long label
  unbalances the whole control.
- Use one content type per control: all text, all icons, or all icon + text.
- Write icon-only tooltips as option names ("Line chart"), not instructions
  ("Switch to line chart").

## Accessibility

SegmentedControl implements the
[WAI-ARIA radio group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/)
via [Ark UI's Segment Group](https://ark-ui.com/docs/components/segment-group):
Tab moves into and out of the group, arrow keys move the selection.

### What SegmentedControl provides

- Each segment is a label wrapping a hidden radio input, so form association
  (`name`) and keyboard behavior are native.
- Icon-only segments take their accessible name from `tooltip`, falling back to
  the item's `value`.
- Inside `Form.Field`, the field's label is associated with the control
  automatically.

### What you must do

- Label the group: wrap it in `Form.Field` or pass `aria-label` — the segment
  labels alone don't say what the choice is.
- Give every icon-only segment a `tooltip`; the fallback accessible name is the
  raw `value` string, which rarely reads well.
