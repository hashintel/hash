## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { TagsInput } from "@hashintel/ds-components";

export const KeywordsInput = () => {
  const [keywords, setKeywords] = useState(["simulation"]);

  return (
    <TagsInput
      name="keywords"
      placeholder="Add a keyword…"
      value={keywords}
      onChange={setKeywords}
    />
  );
};
```

## Examples

### Basic

TagsInput is always controlled — `value` and `onChange` carry the array of
committed values. Enter commits the typed text as a new value; empty or
already-present text commits nothing, and either way the draft clears.

<Stage>
  <DemoState data-harness>
    <TagsInput
      width="md"
      placeholder="Add a keyword…"
      value={["ai", "simulation"]}
      onChange={noop}
    />
  </DemoState>
</Stage>

### Allowing duplicates

A draft matching an existing value normally commits nothing. `allowDuplicates`
accepts it as another occurrence — each occurrence gets its own chip, and
removing one leaves the others in place.

<Stage>
  <DemoState data-harness>
    <TagsInput
      width="md"
      allowDuplicates
      value={["ai", "ai", "simulation"]}
      onChange={noop}
    />
  </DemoState>
</Stage>

### Disabled

`disabled` greys the field, ignores input, and hides the chips' remove
buttons. Prefer `readonly` when the user only needs to see the values.

<Stage>

    onChange={noop}

`invalid` turns the border red and sets `aria-invalid`. Pair it with a

Set `loading` while a lookup or save runs — a spinner appears at the end of
the field. The input stays editable.

### Read-only

`readonly` strips the field chrome entirely and renders the values as plain
chips — use it to display stored lists alongside editable ones. Unlike
`disabled`, the values read as content, not as a greyed-out control.

<Stage>
  <TagsInput width="md" value={["ai", "simulation"]} onChange={noop} />

### Clearable

`clearable` adds a clear button that appears when the field is hovered or
focused and there is something to clear. The default clear empties the values
and the typed draft — `onChange` fires with `[]` — and keeps focus in the
field.

<Stage>
  <DemoState data-harness>
    <TagsInput
      width="md"
      clearable
      value={["ai", "simulation"]}
      onChange={noop}
    />
  </DemoState>
</Stage>

### Chip overflow

`overflow` decides how chips behave when they outgrow the field: `scroll`
(default) scrolls them horizontally, `truncate` collapses the rest into a
"+X" badge while unfocused, and `summary` shows a plain-text list of the
values, falling back to "X selected" once they no longer fit. Focusing a
`truncate` or `summary` field expands it back to chips for editing.

`md` is the default. Use `sm` and below in dense chrome such as toolbars and
table rows, and `lg` for prominent page-level fields; the chips scale with
the field. Give Form.Field the same `size` so the label scales with the

Set the adornment's `variant: "subtle"` to drop its background and divider.

### Custom rendering

`renderSelectedItem` replaces each value's default chip entirely with your own
node — no chip chrome, and no per-value remove button, so removal happens
through the keyboard (Backspace, or the arrow keys plus Delete) and
`clearable`. The value itself stays the identity that duplicates are checked
against and that `onChange` carries, so keep the rendered output recognizably
the value.

export const renderSelectedItemCode = `import { useState } from "react";

import { TagsInput } from "@hashintel/ds-components";

export const KeywordsInput = () => {
  const [keywords, setKeywords] = useState(["ai", "simulation"]);

  return (
    <TagsInput
      width="md"
      value={keywords}
      onChange={setKeywords}
      renderSelectedItem={(value) => <>#{value}</>}
    />
  );
};`;

export const RenderSelectedItemDemo = () => {
  const [keywords, setKeywords] = useState(["ai", "simulation"]);
  return (
    <TagsInput
      width="md"
      value={keywords}
      onChange={setKeywords}
      renderSelectedItem={(value) => <>#{value}</>}
    />
  );
};

<Stage code={renderSelectedItemCode}>

</Stage>

## Behavior

- TagsInput looks and behaves like a multiple Combobox without the dropdown:
  there are no options, so every committed draft simply becomes a new value.
- The typed draft only becomes a value through Enter — leaving the field or
  pressing Escape abandons it.
- Committing empty text adds nothing, and already-present text only commits
  with `allowDuplicates`; the draft clears either way.
- Browser autofill and password managers are always suppressed.

## Content

- Keep values short — a word or two. The row scrolls horizontally once chips
  no longer fit, so long values crowd out their neighbours.
- Placeholders should name the action — "Add a keyword…" — and avoid carrying
  information users must remember: the placeholder only shows while the list
  is empty.

## Accessibility

TagsInput implements its chip row and inline input with the
[Ark UI tags-input machine](https://ark-ui.com/docs/components/tags-input).

### What TagsInput provides

- `name` and `required` are carried by a hidden multi-`select` mirroring the
  values, so validity tracks the committed list rather than the typed draft.
- Labelled controls for pointer interactions: each chip's remove button is
  named "Remove [value]" and the clear button "Clear input".
- Inside a Form.Field the input adopts the field's generated id, so the label
  is associated automatically; `aria-*` props pass through to the `<input>`.

### What you must do

- Always name the input: wrap it in a Form.Field, or pass `aria-label` where
  a visible label genuinely can't fit — a placeholder is not a label.
- Keep `renderSelectedItem` output textual — the value must stand on its own
  for screen-reader announcements to make sense, and custom-rendered values
  have no remove button, leaving removal to the keyboard and `clearable`.
- Don't signal errors with `invalid` color alone — pair it with a message,
  e.g. Form.Field's `errors`.

### Keyboard

| Key                    | Action                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| Enter                  | Commits the typed draft as a new value; empty drafts — and already-present ones without `allowDuplicates` — commit nothing. |
| Escape                 | Abandons the typed draft.                                                                    |
| Backspace              | With an empty draft, highlights the last value, then removes it.                             |
| ArrowLeft / ArrowRight | Move the highlight between values; Backspace or Delete removes the highlighted one.          |
| Cmd/Ctrl + Enter       | Passed through to `onKeyDown` untouched, for form-level shortcuts such as submitting.        |

Enter never submits the surrounding form — it always belongs to the draft.
