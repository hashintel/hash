# TextMark

Keeps a trailing mark — an asterisk, footnote, or icon — attached to the word
before it.

## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { TextMark } from "@hashintel/ds-components";

export const ProjectedRevenueLabel = () => (
  <span>
    Projected revenue<TextMark>*</TextMark>
  </span>
);
```

### When to use

  items={[

### When not to use

<DontList
  items={[
    <>

## Examples

### Basic

Put the mark inside TextMark, written flush against the final word — no space
before it. The word and mark then wrap as one unit.

<Stage>
  <span>
    1,204 entities<TextMark>†</TextMark>
  </span>
</Stage>

### With an icon

A trailing icon is the classic orphan: icons are inline-block, and browsers
will wrap an inline-block onto a line of its own. TextMark removes that wrap
point.

<Stage>
  <span>
    Open run logs
    <TextMark>
      <Icon name="arrowUpRight" size="sm" />
    </TextMark>
  </span>
</Stage>

### With a help tooltip

Interactive marks work too — TextMark is a plain span, so the trigger inside
stays hoverable and focusable.

<Stage>
  <span>
    Sync interval
    <TextMark>
      <HelpTooltip content="How often the integration pulls new records" />
    </TextMark>
  </span>
</Stage>

### Multi-word marks

A space typed before TextMark is a wrap point it can't remove. For a
parenthetical or count, move the joining space inside, where the no-wrap rule
neutralizes it.

```tsx
import { TextMark } from "@hashintel/ds-components";

export const DraftsNavLabel = () => (
  <span>
    Draft entities<TextMark> (12)</TextMark>
  </span>
);
```

### Styled marks

TextMark is unstyled apart from the no-wrap rule; style the mark through
`className`. Margins don't create wrap points, so a small gap before an icon is
safe.

```tsx
import { css } from "@hashintel/ds-helpers/css";

import { Icon, TextMark } from "@hashintel/ds-components";

export const LinkedEntityName = () => (
  <span>
    Acme Corp
    <TextMark className={css({ marginLeft: "[0.3em]", color: "fg.subtle" })}>
      <Icon name="arrowUpRight" size="sm" />
    </TextMark>
  </span>
);
```

### Narrow containers

When the text wraps, the final word and its mark move to the next line
together — TextMark only removes the wrap point between them. The demo
container is 260px wide.

<Stage>
  <div style={{ maxWidth: "260px" }}>
    Entities created by a flow stay in draft until a teammate approves them
    <TextMark>
      <HelpTooltip content="Review pending drafts from the activity feed" />
    </TextMark>
  </div>
</Stage>

## Behavior

- Write TextMark flush against the word before it — a space or `{" "}` in
  between is a wrap point outside its reach. A newline in JSX source collapses
  to nothing and is safe.
- It glues to preceding text and inline elements only. After an image or
  inline-block element the wrap point sits before TextMark; move that element
  inside the mark instead.
- Its content never wraps internally, so keep marks to a glyph, an icon, or a
  short parenthetical — longer phrases overflow narrow containers.
- The glue is a leading zero-width space, which is part of `textContent` and
  copied text — tests that assert on the rendered text must include it
  (`\u200B`).

## Accessibility

TextMark is presentational and adds no interaction of its own.

### What TextMark provides

- A plain `<span>` with no role or accessible name: children keep their own
  semantics, and an interactive mark such as a tooltip trigger stays focusable.
- The leading zero-width space is a formatting character; screen readers don't
  announce it.

### What you must do

- Don't let a symbol carry meaning alone — screen readers may skip `*`
  depending on punctuation verbosity; pair a required mark with
  `required`/`aria-required` on the control, or with visible text.
- Give an icon mark that carries information an accessible name via Icon's
  `alt`; leave purely decorative marks hidden (Icon's default).
