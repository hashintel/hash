## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { CheckboxGroup } from "@hashintel/ds-components";

export const EntityTypeFilter = () => {
  const [value, setValue] = useState<("person" | "company" | "project")[]>([
    "person",
  ]);

  return (
    <CheckboxGroup
      aria-label="Entity types"
      items={[
        { value: "person", label: "Person" },
        { value: "company", label: "Company" },
        { value: "project", label: "Project" },
      ]}
      value={value}
      onChange={setValue}
    />
  );
};
```

## Examples

### Basic

CheckboxGroup is controlled: `value` holds the selected option values and `onChange` receives the full next array — there is no uncontrolled mode. Each item takes a unique `value` plus any Checkbox props, such as `label`, `disabled`, or `tone`.

### Max selectable

`maxSelectable` caps how many options can be checked. At the cap, unchecked options disable; checked ones stay enabled so users can swap a selection. State the limit in the group's description — disabled boxes don't explain themselves.

      items={[

        { value: "personal", label: "Personal" },

### Required

Set `required` to block native form submission until at least one option is checked: while the selection is empty every option is marked required and the group gets `aria-required`; checking any option clears the constraint.

### With a group label

Wrap the group in `Form.Field` with `as="legend"` to give it a visible label, description, and error messages — `as="legend"` names the whole group rather than a single input.

## Behavior

- `onFocus` and `onBlur` fire only when focus enters or leaves the group as a whole — moving between options doesn't retrigger them.
- Options share one `name` for form submission, auto-generated unless you pass one. In a native form post, read the selection with `formData.getAll(name)`.
- `autoFocus` focuses the first option on mount; `"never"` also opts the group out of a containing dialog's or popover's initial focus.

## Content

- Write option labels as short, parallel phrases — sentence case, under 4 words, and with no end punctuation.
- Phrase options positively — "Send weekly digest", never "Don't send weekly digest" — unchecking a negative is a double-negative.
- Order options by likely frequency of use, or alphabetically when there's no natural order.
- When multi-selection isn't obvious, say so in the group's description: "Select all that apply".

## Accessibility

Each option implements the [WAI-ARIA checkbox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/), grouped under a single `role="group"` container. Every option is a native checkbox input wrapped in its label, so label clicks toggle them.

### What you must do

- Always name the group: a visible label via `Form.Field` with `as="legend"`, or `aria-label` when the surrounding context already says what the list is.
- Explain selection caps and disabled options in nearby text — a disabled checkbox doesn't say why it's unusable.
- Pair `invalid` with an error message, e.g. `Form.Field`'s `errors` — the red border alone isn't perceivable by everyone.
