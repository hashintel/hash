## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { useState } from "react";

import { Radio } from "@hashintel/ds-components";

export const VisibilityPicker = () => {
  const [visibility, setVisibility] = useState("workspace");

  return (
    <>
      <Radio
        label="Visible to workspace"
        name="visibility"
        value={visibility === "workspace"}
        onChange={() => setVisibility("workspace")}
      />
      <Radio
        label="Only me"
        name="visibility"
        value={visibility === "private"}
        onChange={() => setVisibility("private")}
      />
    </>
  );
};
```

Radio is always controlled: `value` holds whether this option is selected and
`onChange` reports selection (see Installation for the group wiring). The
default is `md`-sized and `neutral`.

A disabled radio keeps its selected state visible but can't be changed.

constraint nearby.

### Tones

`tone` colors the selected circle: `neutral` (default) for everyday forms,
`brand` for primary flows such as onboarding, `success` for
confirmation-flavored choices. Unselected radios look the same in every tone.

### Label placement

`labelPlacement` puts the label `right` (default) or `left` of the circle.
With `left`, the root also spreads label and circle to opposite edges once you
give it a width via `className`.

### Label alignment

`labelAlign` sets the circle against a label that wraps onto several lines:
`top` (default) pins it to the first line, `center` centers it against the
whole label.

### In forms

The selected radio submits its `htmlValue` (default `"on"`) under `name`;
nothing submits while the group is unselected. `required` blocks native
submission until one option in the `name` group is chosen.

```tsx
import { useState } from "react";

import { Button, Radio } from "@hashintel/ds-components";

export const ExportScopeForm = () => {
  const [scope, setScope] = useState<string | null>(null);

  return (
    <form action="/api/exports" method="post">
      <Radio
        label="Current view"
        name="scope"
        htmlValue="view"
        required
        value={scope === "view"}
        onChange={() => setScope("view")}
      />
      <Radio
        label="Entire workspace"
        name="scope"
        htmlValue="workspace"
        required
        value={scope === "workspace"}
        onChange={() => setScope("workspace")}
      />
      <Button type="submit" tone="brand">
        Start export
      </Button>
    </form>
  );
};
```

## Behavior

- RadioGroup renders as one `<label>` wrapping a
  hidden native radio, so clicking anywhere on it selects. Don't nest it inside
  another label or interactive element.
- Selection is one-way from the user's side: clicking a selected radio fires
  nothing, and `onChange` only ever reports `true`. Clearing or switching
  happens through your state, by selecting a different option.
- Radios sharing a `name` get native arrow-key behavior, but each one stays
  controlled.
- Long labels wrap rather than truncate by default

## Content

- Name the option, not the action: “Entire workspace”, never “Select entire
  workspace”. Sentence case, no terminal punctuation.
- Phrase every option in a set with parallel structure — all nouns or all verb
  phrases — so the differences stand out.
- Keep labels under roughly 5 words and one line; move caveats into nearby
  helper text.
- For optional choices add a “None” option — a group can't be
  returned to unselected once the user picks.

## Accessibility

Radio renders a native
[`<input type="radio">`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/radio).
Grouped under a shared `name`, and implements the
[WAI-ARIA radio group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/)'s
interaction model.

### What Radio provides

- A visually hidden native `<input type="radio">` inside a `<label>`.
- With a shared `name`, the native inputs handle Tab and arrow keys.

### What you must do

- Always provide `label` — without it the input has no accessible name. When
  the visible label lives elsewhere, pass `htmlForId` and point that label's
  `htmlFor` at it.
- Name the group as a whole: wrap custom groups in `role="radiogroup"` with an
  `aria-label`, or a `<fieldset>` with a `<legend>`.
- `invalid` is visual only — put error text next to the group, since nothing is
  announced otherwise.
- Use a shared `name` across the options so the browser groups the inputs for
  arrow-key navigation and form submission.
