## Installation

1. Install the package.

```sh
npm install @hashintel/ds-components
```

2. Import the component.

```tsx
import { LoadingSpinner } from "@hashintel/ds-components";

export const EntityTableLoading = () => <LoadingSpinner size="md" />;
```

## Examples

### Basic

The default spinner is a smooth circular sweep at `md` (24px). Drop it into
the space the pending content will fill.

<Stage>
  <LoadingSpinner />
</Stage>

### Sizes

Five fixed sizes from `xxs` (8px) to `lg` (32px), sharing the scale Button and
the form inputs use — match the control or region the spinner stands in for.

<Stage>
  <LoadingSpinner size="xxs" />
  <LoadingSpinner size="xs" />
  <LoadingSpinner size="sm" />
  <LoadingSpinner size="md" />
  <LoadingSpinner size="lg" />
</Stage>

### Bars variant

`bars` replaces the smooth sweep with twelve spokes that tick in discrete
steps. Its thinner strokes stay legible at small sizes — it's what Button
renders in its `loading` state.

<Stage>
  <LoadingSpinner variant="default" size="md" />
  <LoadingSpinner variant="bars" size="md" />
</Stage>

### Color

Both variants draw entirely with `currentColor`, so the spinner takes the CSS
`color` of its container — style the wrapper, or pass a `className`.

<Stage>
  <LoadingSpinner size="md" />
  <span style={{ color: "#0d74ce", display: "inline-flex" }}>
    <LoadingSpinner size="md" />
  </span>
  <div
    style={{
      backgroundColor: "#1d1d1d",
      color: "#ffffff",
      padding: 12,
      borderRadius: 8,
      display: "inline-flex",
    }}
  >
    <LoadingSpinner size="md" />
  </div>
</Stage>

### With a label

A spinner alone doesn't say what's loading. Pair it with text naming the work,
and wrap both in `role="status"` so screen readers announce it too.

<Stage>
  <div role="status" style={{ display: "flex", alignItems: "center", gap: 8 }}>
    <LoadingSpinner size="sm" variant="bars" />
    <span>Loading entities…</span>
  </div>
</Stage>

### Inside a button

Set Button's `loading` prop instead of slotting in a spinner yourself — it
renders a `bars` spinner sized to the button, keeps the button's width, and
announces busy to assistive technology.

<Stage>
  <Button loading tone="brand">
    Creating entity
  </Button>
  <Button loading variant="subtle">
    Running flow
  </Button>
</Stage>

## Behavior

- Both variants animate with CSS keyframes — no JavaScript timers: `default`
  sweeps continuously (one revolution per 1.1s); `bars` ticks through its
  twelve spokes in discrete steps.
- The animation keeps running under `prefers-reduced-motion` — a frozen
  spinner reads as a stalled process, not a calmer one.
- Sizes are fixed pixel squares (8–32px); the spinner doesn't scale with
  surrounding text or its container.

## Accessibility

### What LoadingSpinner provides

- A decorative SVG with no role, accessible name, or live region — assistive
  technology hears nothing from it; motion is the only built-in signal.

### What you must do

- Announce loading in text: wrap the spinner and a label in an element with
  `role="status"` so screen readers hear the state change.
- Name the work in the label — "Loading entities…", not "Please wait".
- Inside Button, set `loading` instead — it applies `aria-busy` and a polite
  live region for you.
