## Using color tokens

Pass token names to any color-accepting property in `css()` or a recipe. Tokens
resolve per theme, so the same name is correct in light and dark.

```tsx
import { css } from "@hashintel/ds-helpers/css";

export const EntityCard = () => (
  <div
    className={css({
      backgroundColor: "bg.surface",
      border: "1px solid {colors.bd.subtle}",
      color: "fg.body",
    })}
  >
    Person
  </div>
);
```

## Token layers

Color is layered the same way in Figma and code: raw values feed core palette
scales, and semantic aliases name what a color is *for*. Reference the highest
layer that exists for your case — intent survives refactors, raw values don't.

| Layer          | Example               | What it encodes                                        |
| -------------- | --------------------- | ------------------------------------------------------ |
| Raw value      | `#ef4444`             | Nothing — never appears in product code                |
| Core scale     | `red.s60`             | A palette position, light/dark aware                   |
| Semantic alias | `status.error.fg.body` | The role: error-toned body text, states included      |

## Palettes

Eight palettes, each with a solid scale (`s00`–`s125`) and an alpha scale
(`a00`–`a125`) in steps of 5. Alpha steps are translucent layers of the same
hue — they tint whatever they sit on, which keeps layered UI (hover states,
selections) consistent on any background.

| Palette   | Role                                                 |
| --------- | ---------------------------------------------------- |
| `neutral` | Default UI: text, borders, surfaces                  |
| `blue`    | Brand, links, selection; aliased as `status.info`    |
| `green`   | Positive outcomes; aliased as `status.success`       |
| `orange`  | Caution; aliased as `status.warning`                 |
| `red`     | Errors and destructive actions; `status.error`       |
| `yellow`  | Highlights and emphasis accents                      |
| `pink`    | Accent and data visualization                        |
| `purple`  | Accent and data visualization                        |

### Scale anatomy

The semantic aliases pin down what each band of a scale is for — follow the
same bands when you use scale steps directly.

| Band      | Steps                | Used for                                                  |
| --------- | -------------------- | --------------------------------------------------------- |
| `00`–`50` | alpha preferred      | Fills: `surface` is `a10`, `subtle` is `a30`, `shaded` is `a50` |
| `40`–`80` | alpha                | Borders: `subtle` is `a40`, `solid` is `a60`, `strong` is `a80` |
| `90`–`100` | solid               | Solid accents: `bg.solid` is `s90` (`s125` for neutral), hover `s100` |
| `90`–`125` | solid               | Text: `subtle` `s90` up to `max` `s125`                    |

## Semantic aliases

Every palette carries the full semantic set (`blue.fg.link`, `red.bd.solid`),
and the same set exists at the root referencing `neutral` (`fg.muted`,
`bg.surface`). The bare name is the resting state; interaction states nest
under it: `bg.surface`, `bg.surface.hover`, `bg.surface.active`,
`bg.surface.disabled`.

export const SemanticSwatches = () => {

    <div
      style={{

        fontSize: token("fontSizes.xs"),
        color: token("colors.fg.muted"),

                width: 84,

                border: "1px solid " + token("colors.bd.subtle"),

### Backgrounds

`bg.*` layers are alpha-based so they compose on any surface; `bgSolid.*` is
the opaque equivalent of every group, for surfaces that must not blend —
popovers, dialogs, dropdowns.

| Token        | Resting value | Use                                              |
| ------------ | ------------- | ------------------------------------------------ |
| `bg.min`     | `a00`         | The page itself; hover/active add the first tint |
| `bg.surface` | `a10`         | Cards and contained regions                      |
| `bg.subtle`  | `a30`         | Emphasized fills: selected rows, active nav      |
| `bg.shaded`  | `a50`         | Strong fills that still read as background       |
| `bg.solid`   | `s90` (`s125` for neutral) | Accent surfaces: solid buttons, badges |

### Foregrounds

| Token        | Value  | Use                                            |
| ------------ | ------ | ---------------------------------------------- |
| `fg.max`     | `s125` | Maximum contrast, sparingly                    |
| `fg.heading` | `s120` | Headings                                       |
| `fg.body`    | `s115` | Body text                                      |
| `fg.muted`   | `s100` | Secondary text: captions, helper text          |
| `fg.subtle`  | `s90`  | The quietest readable text: placeholders       |
| `fg.link`    | `s110` | Links, with hover/active/disabled states       |
| `fg.onSolid` | —      | The contrast color for text on `bg.solid`      |

### Borders

| Token       | Value | Use                                         |
| ----------- | ----- | ------------------------------------------- |
| `bd.subtle` | `a40` | Hairlines and dividers                      |
| `bd.solid`  | `a60` | Input and card borders                      |
| `bd.strong` | `a80` | Emphasis and selected outlines              |

## Status colors

`status.{info,success,warning,error}` alias the blue, green, orange, and red
palettes — scales and semantic sets included. Use them whenever a color means
an outcome, so the meaning stays explicit in code.

## Static colors

`black` and `white` with alpha scales (`black.a00`–`black.a125`) keep a fixed
value in both themes. Use them for overlays tied to content rather than theme:
scrims behind dialogs, gradients over images.

## Switching palettes with colorPalette

Recipes can defer the palette choice to Panda's `colorPalette` property: style
against `colorPalette.*` once, and switch the whole component's hue with a
single property — Chip and Banner implement their tone variants this way.
Only the semantic groups (`bg`, `bgSolid`, `fg`, `bd`) are available through
`colorPalette`; scale steps like `colorPalette.s110` don't resolve.

```tsx
import { css } from "@hashintel/ds-helpers/css";

const tag = css({
  colorPalette: "purple",
  backgroundColor: "colorPalette.bg.surface",
  borderColor: "colorPalette.bd.subtle",
  color: "colorPalette.fg.body",
});
```
