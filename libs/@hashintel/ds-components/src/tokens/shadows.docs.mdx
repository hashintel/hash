## Using shadow tokens

Reach for the semantic `elevation.*` tokens: they name how far a surface sits
above the page, and each level comes tuned for large and small surfaces. The
raw `shadows.*` scale underneath is for cases no elevation level covers.

```tsx
import { css } from "@hashintel/ds-helpers/css";

export const TypePopover = () => (
  <div
    className={css({
      backgroundColor: "bgSolid.min",
      borderRadius: "lg",
      boxShadow: "elevation.raise.macro",
    })}
  >
    …
  </div>
);
```

### When to use

<DoList
  items={[

    "Use macro for large surfaces (cards, panels, dialogs) and micro for small ones (buttons, badges, menu items).",
    "Pair shadows with an opaque bgSolid background — translucent surfaces make the shadow read as a smudge.",

### When not to use

<DontList
  items={[
    "Don't hand-write box-shadow values — one-off shadows break the depth hierarchy and don't track theme changes.",
    "Don't stack elevation on nested elements — one shadow per surface; children separate with borders and background shifts.",
    "Don't use shadows as borders — at rest on a flat surface, bd.* tokens are the right tool.",
  ]}
/>

## Elevation tokens

Four levels, each in a `macro` and `micro` size:
`elevation.{drop,lift,raise,float}.{macro,micro}`. Macro suits large surface
areas; micro keeps the same depth believable on small footprints.

| Level   | Reads as                      | Typical surfaces                  | Macro | Micro |
| ------- | ----------------------------- | --------------------------------- | ----- | ----- |
| `drop`  | Resting just above the page   | Cards, inputs at rest             | `xs`  | `2xs` |
| `lift`  | Slightly raised               | Hover emphasis on cards and rows  | `sm`  | `xs`  |
| `raise` | Clearly above the content     | Dropdowns, popovers, tooltips     | `md`  | `sm`  |
| `float` | Detached from the page        | Dialogs, drawers, command bars    | `lg`  | `md`  |

## Base scale

Seven steps from a hairline of depth to a heavy overlay glow. Elevation
tokens map onto this scale; use it directly only when no semantic level fits,
and expect such uses to be rare.

| Token | Use                                                 |
| ----- | --------------------------------------------------- |
| `2xs` | The faintest edge definition                        |
| `xs`  | Resting depth on large surfaces                     |
| `sm`  | Gentle lift                                         |
| `md`  | Overlay depth                                       |
| `lg`  | Detached overlays                                   |
| `xl`  | Oversized feature surfaces                          |
| `2xl` | Maximum depth — hero and marketing moments          |

export const ShadowScale = () => {
  const steps = ["2xs", "xs", "sm", "md", "lg", "xl", "2xl"];
  return (
    <div
      style={{
        display: "flex",
        gap: 24,
        flexWrap: "wrap",
        padding: 24,
        borderRadius: 8,
        background: token("colors.bgSolid.surface"),
        fontFamily: token("fonts.mono"),
        fontSize: token("fontSizes.xs"),
        color: token("colors.fg.muted"),
      }}
    >
      {steps.map((step) => (
        <div key={step} style={{ textAlign: "center" }}>
          <div
            style={{
              width: 76,
              height: 76,
              borderRadius: 8,
              background: token("colors.bgSolid.min"),
              boxShadow: token("shadows." + step),
            }}
          />
          <div style={{ marginTop: 8 }}>{step}</div>
        </div>
      ))}
    </div>
  );
};

### Inset shadows

Three inset steps — `inset-2xs`, `inset-xs`, `inset-sm` — recess a surface
into the page: wells, pressed states, scroll gutters.
