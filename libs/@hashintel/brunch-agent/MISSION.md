## Imperative

Keep a long Brunch interview usable without silently sacrificing its recoverable account or leaving the person in an indefinitely busy turn. The Ledger must retain its section structure and provenance unless the user explicitly retracts material; repeated fresh-base net observations must stop accumulating in model context; provider streams must recover visibly from bounded inactivity without replaying admitted work; and tool rows must make pending versus settled work visually distinct. Measure the remaining whole-document settlement cost after those protections so Lu can decide whether a separately recut section-operation throughline is necessary.

Why now: Mission 7d crossed the real browser-visible path far enough to expose the next load-bearing failure. The current system can continue constructing, but it does so while approaching context limits and allowing the model to discard most of the Ledger to reduce its own upload cost. Another full demo run before protecting that boundary would spend money to reproduce a known failure.

### Work packages

#### WP-A — No silent Ledger shrinkage

Keep the full-body Stage 1 input. Compare the candidate with the authoritative base inside `mutate_workpiece` and refuse the whole settlement through the existing tool-error channel when it drops any existing heading or exceeds a stated size-loss threshold, unless an explicit retraction names the user-withdrawn material, lists unique, non-overlapping prior-Ledger excerpts that the replacement removes and whose total length covers any large net reduction, quotes the exact authorization text and cites the true-user message containing it. Source identity or a free-text reason alone cannot authorize provenance deletion; the dedicated retraction shape persists the name, loss-accounting excerpts, quote and source ids. The refusal reports missing headings and character delta and states that nothing was written. First revisions are unguarded; ordinary growth passes; an already-applied call remains an idempotent replay.

The core prompt and elicitation skill state the same rule without Inventory nouns: carry the complete settled account forward, edit only changed passages, remove headings or sections only for an explicit user retraction, and name why any accepted body is shorter. A refusal for one bad evidence relation is repaired and resubmitted without dropping the other relations. The guard, not prose, proves preservation.

#### WP-B — Net-observation economy

In the model-only projection, keep the latest full successful `read_petrinaut_net` body and reduce each superseded read to `{ observation: { toolCallId, sha256 }, counts }`. Canonical entries, browser output and public history remain byte-for-byte untouched. Projection must decide authority from exactly the slice it receives, preserve entry count/order/identity, and never point to a body outside that slice.

Measure the implemented projection in the fresh paid run through actual cached-token growth and compaction behavior. Do not block that observation on replaying retained `run-SB5pgx` context. Admit a compact model rendering only if the fresh run shows that dedupe alone does not meet the Stage 1 context discriminator; use historical replay then only if needed to isolate the residual pressure. Any rendering must omit only model-irrelevant layout/default noise while preserving every structural and semantic field needed to inspect the current net and the exact observation identity required by `mutate_petrinaut_net` and `query_workpiece`.

#### WP-C — Visible lifecycle and carried contract closure

Pending ordinary tool rows use a gold/yellow basis, settled rows green and errors red, without changing stable tool identifiers or hidden automatic-tool behavior. Close the predecessor review items that intersect this mission: re-point `test:passage-policy` and `test:workpiece-evidence` to the current text-evidence input; add the missing `acceptLive` contiguity discriminator; keep failed/stale mutations from displacing the recovery ledger; preserve usable `[message <id>]` citation authority across compaction by recovering settled evidence ids from the Ledger and resolving their canonical sources; literal ids need not survive in the provider-written summary; remove duplicate `output.observation` promotion when the net-read contract is touched, leaving one authoritative producer; and run the website integration suite. #### WP-D — Bound provider-stream idleness and recover once

Build the red loop first at the registered native OpenAI/browser seam: reasoning starts and completes, a function call starts and emits one argument delta, then the provider stream remains open without `response.output_item.done` or `response.completed`. The real live channel must show thinking plus an `input-streaming` `mutate_workpiece` row while canonical history has no admitted tool call. Test thresholds use milliseconds; production uses 10 seconds after request dispatch and after meaningful progress, with one narrow 15-second grace after `reasoning_start` before its first delta or completion. Heartbeats and an open socket are not progress.

When the clock expires, publish a typed content-free idle disposition carrying attempt/request correlation, phase, last meaningful event kind and idle duration; mark the speculative row as recovering; abort upstream; and wait at most 2 seconds for acknowledgement. If canonical admission wins the race, it wins and no automatic retry occurs. If cancellation wins and no tool was admitted, ignore all late events from that attempt and start exactly one visible invocation with the same model/reasoning from the latest canonical conversation tail. Do not append partial reasoning/arguments, replay the user message, rerun completed server/browser tools, overlap attempts, change model, or hide known/unknown request cost. A repeated idle or unacknowledged cancellation terminalizes the submission red.

The launcher Stop path must request Flue abort and await a bounded settlement before stopping owned services so the submission row, speculative-row terminal state and F.6 chronology are retained. A forced shutdown remains possible after the grace, but it must record that graceful settlement was not obtained. This observability repair is part of the liveness contract, not proof of the upstream cause.
