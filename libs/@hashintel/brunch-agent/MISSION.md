##### Result contract

Replace expected `mutate_workpiece` validation exceptions with one discriminated output union. Exact field names may be improved locally, but the semantics are fixed:

```ts
type MutateWorkpieceResult =
  | {
      disposition: "applied";
      applied: true;
      revisionId: string;
      sha256: string;
      ordinal: number;
      // validated evidence, retraction and mutation receipt as today
    }
  | {
      disposition: "refused";
      applied: false;
      correctable: true;
      code: WorkpieceRefusalCode;
      message: string;
      currentRevision: WorkpieceRevisionPointer | null;
    };
```

Use exactly this finite `WorkpieceRefusalCode` set: `"replay-conflict" | "stale-base" | "concurrent-revision" | "evidence-invalid" | "retraction-invalid" | "silent-shrink"`. Evidence text/source failures share `evidence-invalid`; retraction authorization, excerpt accounting and named-removal failures share `retraction-invalid`; missing headings and excessive shrink share `silent-shrink`. The message remains the current specific correction instruction, including “Nothing was written” where applicable. The current pointer gives the model an authoritative retry base without inventing a read.

Do not turn every exception into a refusal. Abort/cancellation, retained-state corruption, persistence or source-read failure, output-schema defects and unknown exceptions must still throw and render red. Pre-execution `updateWorkpieceInputSchema` parse failure remains a Flue/Pi tool error and red in this slice; the model-facing schema remains strict and unchanged.

The successful branch gains `disposition: "applied"` and `applied: true`; downstream consumers must narrow the union rather than infer success from field presence. Replay with identical Markdown remains applied/idempotent and preserves its original ordinal. The refused branch returns with `terminate: false`, writes no revision/evidence/hash/ordinal, and lets the ordinary agent loop decide whether to submit another call.
