## Production joins

### Core revision and declared basis

`useBrunchAgent(model, compaction?, consumeRevision?)` exposes its one render's existing `WorkpieceRevision | null` through an additive composition callback. The original prompt return, single model/compaction declaration, single persistent-state registration, core-owned non-interactive question marker, and durable non-terminating `update_workpiece` remain intact. The plugin receives that exact authority from ChatAgent; it does not register another state key or reconstruct current state from fenced prose.

The joined mutation adds one `brunch` envelope beside mechanically derived canonical `addArc` arguments. Basis is `declared { revisionId, sha256, locators, rationale, scope: "operation", supersessionIntended? }` or `absent { reason }`. Locators are immutable revision-local UTF-16 spans, not stable passage identities or cross-revision continuity. Unknown revisions refuse even with intended override. Superseded revisions require an explicit override and a retained successful core revision call with matching content hash. The app acquires only this already-authorized instance's public SDK history through the existing router for historical citations and receiving-boundary checks; no companion history store or generic lookup API was introduced.

The skill and its workpiece template now teach full-document settlement and explicit settled identity rather than a second newly emitted fenced authority. Universal elicitation methods and uncertainty/authorship rules are unchanged. The legacy prepared mode's existing fenced protocol and consumers remain labelled legacy; the opt-in tracer does not use them as its current revision authority.

This is identity/span validation, not proof of evidential relevance, full template conformance, passage continuity, or useful explanation. The browser fixture deliberately cites a broad prepared span and explicitly disclaims useful-basis and elicited-testimony claims.

### Structural input and publication

The opt-in root arc uses native normalization → structural canonical carrier → canonical Petrinaut validation. Its exported local schema equals the canonical root contract with only the `brunch` property/required entry added (JSON Schema dialect markers are excluded from that comparison, as in the inherited local carrier tests). It preserves root strictness, descriptions and canonical nested constraints without hand-copying Petrinaut fields. It admits root place arcs only. The headless catalogue and other operation carriers are unchanged.

**Observed strain:** Flue emits raw `tool-input` before its server tool validation finishes. The inherited transport also ignored client-tool validation errors. A basis check in `run` alone would therefore leave executable browser work available too early. The minimal opt-in `validatedClientToolNames` transport setting now exposes a loading call identity, but withholds executable input until the corresponding server tool succeeds; rejection emits the matching error. The same setting prevents pending/unvalidated snapshot calls from becoming executable after hydration. Unselected/legacy transport timing is unchanged.

Canonical history retains the original call ID and arguments, including the basis envelope and the model's numeric-string weight. The browser projection normalizes that weight and strips only `brunch` before Petrinaut execution. The transition request contains the canonical normalized input. This does not rewrite Flue's canonical raw arguments or turn local normalization into provider-facing schema fidelity.

### Binding, observation, result carriage

The opt-in fixture uses a separate document, a creation-time persisted incarnation, and an original base hash observed from its actual handle before issuing requests. Its conversation ID is `prepared-root-arc:<incarnationId>`; neither it nor the document aliases the fixed legacy fixture. Binding/base are immutable initial data and are also carried in the existing prepared dispatch for honest reopen comparison because public history does not expose initial data. The ownership guard refuses an initial binding naming another authenticated conversation. Preparation refuses a reused conversation with a different incarnation or requested base.

The existing A3 recorder is mounted as `aiAssistant.executeMutation` only on the opt-in route. One stable recorder owns the active handle/conversation lifetime. Its issued-call map checks both canonical request identity and the complete basis envelope against replacement. A3 independently snapshots the handle immediately before/after the synchronous canonical callback, checks the requested base/incarnation, derives disjoint effects, accounts for the full canonical diff, and prevents duplicate execution.

The existing `client-tool-result` signal retains canonical `toolCallId`, `toolName`, and `output`, adding only `metadata.transitionRecord`. Its existing latest-client-step selection and stable ordering remain intact. The receiving ChatAgent hook verifies the sidecar against the successful issued call, bound conversation/document/incarnation and requested base, then recomputes hashes/effects/outcome before model continuation. It checks both the signal type and tag. Contradictory deliveries remain in canonical history, fail continuation, and project as an unknown/error outcome rather than replacing an earlier result with success. This is the narrow call-result join, not an A5 attribution API.
