# R2 connection gates in progress

The parent ran a connection-only controller under the frozen paid profile against the frozen browser owner under a separate loopback profile. Launcher27111, owner27114, Chrome27127, controller27139. The controller used the actual private binding/claim and public Playwright connection, checked its parent identity and external-port80 EPERM, clicked the real page and read `Paid controller reached loopback browser`. With no route interception or `exposeNetwork`, Chrome's numeric external443 navigation returned ERR_ACCESS_DENIED. Both Node roots and Chrome subsequently exited, the profile/readiness/binding were removed and the library endpoint returned ECONNREFUSED. No application/model/provider request was made.

The subsequent fixed-host lookup of `api.anthropic.com` under the TCP443-only profile returned `getaddrinfo ENOTFOUND`; no TLS or provider HTTP request followed it. Preserve this failure. It does not by itself prove the hostname is unavailable globally or authorize an unguarded retry.

Under the same named allocation, the parent authorizes a **DNS-only metadata profile** for resolving that one public hostname: UDP/TCP53 egress and required UDP binding, no HTTP/TLS/provider/application/SDK code or credential environment. The frozen driver and browser profiles are not widened or edited, and native transport still uses only the final explicitly approved numeric IP. This is a guarded bootstrap metadata step, not a fallback model request or credential probe. Its outcome and any further failure must remain visible before TLS/invocation.
