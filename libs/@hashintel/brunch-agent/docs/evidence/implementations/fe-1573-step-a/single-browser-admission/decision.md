# Single-browser proposal admission decision

A remaining documented admission gap was probed after A5/recovery integration at alpha `963c0054dc`. The actual built ChatAgent mount received one synthetic proposal containing valid `getLatestNetDefinition {}` and invalid native `addType { id: "invalid-type" }`, with no client-result submission. The competing safe behavior would reject the whole proposal or wait for the admitted read's result despite the invalid sibling.

Observed: the read settled server-side as `{ awaiting: "client" }`, the native mutation correctly failed validation, and the model made a second request and emitted `CONTINUED_WITHOUT_CLIENT_RESULT`. The retained report has `providerCalls: 2`, `clientResultSignals: 0`, `continued: true`. This is an actual mounted causal-result gap, not a physical browser mutation or a paid-provider result. The small probe ran under the existing deny-network profile, used a fresh original SQLite store and substituted only the underlying provider with the existing faux mechanism. Source, command output and public history are retained losslessly here; no stored history was fabricated or imported.

Under Lu's AFK delegation, the integration owner chose fail-closed single-browser proposals for the existing scoped ChatAgent provider boundary. A proposal with more than one logical browser call is rejected before publication/execution; a single browser call still waits for its own result. Server-only proposals and unrelated provider/transport consumers remain unchanged. The same call's streamed/final representations must not be counted twice, and duplicate/inconsistent identities must not permit multiple executions. This does not change Flue termination aggregation, add a proposal ledger or automatically repair/retry rejected submissions.

Rationale: one serialized external result boundary is sufficient for the current and next construction consumers; allowing mixed-validity browser batches requires a stronger batch contract that is not implemented. Prompt wording alone cannot repair the observed ordering. The additional model round trips stay inside the existing budget. This policy change is recorded in the separate Mission authority commit before implementation, with exact mounted and provider-boundary regressions required. Prior single-browser A5 evidence remains valid; it never claimed universal multi-browser safety.
