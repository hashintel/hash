## Production boundaries

**S and F.** Petrinaut owns the 47-tool canonical catalogue, schemas, execution and result semantics. Native S uses the website's `/api/chat` handler and Petrinaut's built-in panel tools. F carries that same prompt/catalogue over Flue without Brunch's Ledger, draft, provenance claims or mutation sidecars. F's built-browser `addPlace` witness proves transport and persistence, not equivalence of model choices to S.

**I, A and B.** `ChatAgent` mounts the SDCPN plugin and classifies the full Petrinaut catalogue without redeclaring schemas. I adds the Brunch workpiece/Ledger substrate and reviewed draft. A additionally declares model-authored *intent* with literal Ledger excerpts; the server resolves the current revision and locators, while later canonical calls remain separate Petrinaut executions. B additionally offers bounded `apply_petrinaut_construction`; the browser privately resolves binding, Ledger bases and live document state, executes a successful prefix, settles revisions and records verified effects. A/B remain available and **unselected**; an expected impact is `owner-adjudication-required`, not automatically satisfied.

**Browser and document truth.** `LocalStorageDemoApp` binds a Flue conversation to the document/incarnation, passes the current handle into Petrinaut, subscribes to its change events, and persists emitted repository revisions. `PetrinautDocHandle` supplies change/revision truth; a handle event or `applied: true` output alone does not prove a settled repository write or associate a call with that write. The host overrides only the canonical read/diagnostic and root `addPlace`, `addTransition`, `addArc` names needed for verified records; the remaining canonical tools still execute in Petrinaut. An in-flight root record stays in its adapter through repository rerenders by a stable settlement-action callback; the B adapter authorizes a copied UI input through a private, issued-call-bound record and host receipt rather than trusting a serialized authority object.

**Flue evidence.** F/A/B deliver browser results through a later Flue signal; I returns issued canonical browser results within the running Flue tool call through a process-local, capability-bound route. The server checks the issued call, document binding, result and required sidecar before accepting it; only the canonical Petrinaut output reaches the model, while the verified record stays in Flue history. The Ledger is a projection over that history, not another event or revision store. A verified root mutation or B construction can claim bounded call-to-settled-change causation; an I mutation with a lost or invalid result instead remains `unrecorded` and invalidates the preceding read, while a proved-unstarted call is not counted as a document change. A direct `createExperiment` yields a verified, source-bound **non-document-mutating** experiment event. An unexecuted draft is not a document cause. All six canonical scenario/metric add/update/remove calls execute and persist through Petrinaut but currently lack Brunch per-call evidence by owner policy, so their Ledger events are `unrecorded`. This means *no verified call-to-saved-change correlation*, not unchanged or unsaved. For canonical definition reads, Brunch verifies the correlated definition observation; the accompanying `title` and `extensions` are Petrinaut's browser output, not independently attested by Brunch.

**Experiment authority.** For a Ledger-derived integrated proposal, Brunch prefers `draft_petrinaut_experiment` after a verified canonical read and settled Ledger. The server authorizes the issued draft; the browser independently checks history and the live handle before preparing it. The Flue result is `drafted` or `invalid`; later human Run/Dismiss belongs to editor-local draft state and Run uses Petrinaut's `experimentHost.runExperiment` and shared card. Explicit immediate canonical `createExperiment` remains available in S/F/I/A/B and uses that same host directly. The request carries no Brunch constraints API; `unsupported.blocksRun: false` is disclosed model judgment, not host-verified consent.
