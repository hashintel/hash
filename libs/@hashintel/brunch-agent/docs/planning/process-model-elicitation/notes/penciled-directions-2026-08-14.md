1. **Schema as forcing function — techniques compile into machinery via payload interiors.** A technique expressed as prompt guidance depreciates; the same technique expressed as a field shape appreciates: a quantity field _typed_ as quantile-triple (p10/p50/p90) forces quantile elicitation because the store refuses a point estimate. FE-1405 is therefore not just "define the shapes" — it is the compilation step from layer 2 to layer 3, and each interior field should be audited for "which technique does this field force?" → Action: add this framing to FE-1405 when it starts; the audit's per-technique entries name the candidates.

2. **Plugin manifest sketch (Lu).** Top-level plugin properties, largely serializable (YAML-ish): licenses / techniques / movements (slice_moves, sweep_moves) / scopes_and_motifs / rabbit_holes / failure_modes / smells / lenses / checks (tool-using) / tools / ontology / schema. Maps onto the three prompt mechanisms + machinery + ontology — the layer model as a manifest. Gaps noticed at pencil time: **completion contract / anchor declaration is absent**; absence-handling policy and evidence policy are envelope-level but the plugin may need declared postures. Ownership sort needed per key (vocabulary-ownership rule): generic licenses and failure modes are quiver/harness-side; domain instances are plugin-side. → Action: candidate structure for plugin-spec authoring; test-fit against the smallest honest plugin (spec §11.3) and Gherkin before CPS.

   > **Reflection:** The manifest works because it serializes the layer model — licenses/techniques plus the attention-shaped keys (scopes*and_motifs, lenses, smells) are the three prompt mechanisms; checks/tools are machinery; ontology/schema is FE-1405. `rabbit_holes` is quietly the most novel key: anti-guidance — where \_not* to dig — which nothing in the imported literature covers and which the baseline's budget-burning behaviors argue is real. The ownership sort will split single keys in two: "you may press a busy expert" is an envelope-vocabulary license (quiver-side) while "press on tint-qualification claims" is the same key plugin-side. And the test-fit order matters because a manifest that only fits the thick case is a thick-case schema, not a plugin contract.

The harness's settlement/sweep vocabulary and re-entry briefing already support oscillation; guidance must present modes as postures, not a state machine — conversation stays primary. → Action: name the oscillation explicitly in FE-1403's movement guidance; check FE-1402's contract behaves sanely under re-opened scopes (completion is monotone over captures, not over conversation phases).

   > **Reflection:** The slice-and-trace / sweep-bias mapping matches how the settlement vocabulary already works — veins close, ranges settle, sweeps harvest — another instance of the experiment and the architecture cutting at the same joints without coordination, which is soft confirmation of both.

4. **Activation probes as a card-economy instrument.** Before writing any technique card, probe whether the name alone activates the content: ask the substrate model cold to describe "premortem", "Critical Decision Method", "ACTA knowledge audit", etc. If the probes reproduce from the name, the card collapses to name + when-to-use (cheap, model-portable); if not, the card must carry content (expensive, depreciating). Bano specifically: niche academic — name-activation unreliable, and its content targets novice mistakes the model doesn't make; low elicitor value, scoring-side value only. → Action: run activation probes as step one of FE-1403; record per-technique results next to the mechanism type.
