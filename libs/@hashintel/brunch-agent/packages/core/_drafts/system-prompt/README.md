# Brunch core system-prompt workbench

**Temporary, non-authoritative material.** The production prompt is [`../../src/SYSTEM.md`](../../src/SYSTEM.md). Nothing in this directory is imported or built.

This workbench turns the [core elicitor prompt audit](../../../../docs/evidence/audits/core-elicitor-prompt-material-audit-2026-08-31.md) into text that can be manually cut, combined, shortened, or promoted into `SYSTEM.md`. It intentionally contains overlapping formulations. Similar wording here is a design comparison, not corroborating evidence.

## Browse by use

- `assemblies/` contains complete prompt candidates with different emphases.
- `sections/` contains interchangeable prompt modules, usually short / medium / strong variants.
- [`source-map.md`](source-map.md) maps modules back to repository evidence and open questions.
- [`exclusions-and-false-claims.md`](exclusions-and-false-claims.md) lists material that must not leak into a generic or truthful core prompt.

## Suggested shaping workflow

1. Choose an assembly closest to the desired register.
2. Replace individual paragraphs from the corresponding section files.
3. Remove repeated rules; one authoritative statement is better than several paraphrases.
4. Keep detailed interviewing techniques out of `SYSTEM.md`; they belong in a future generic elicitation skill.
5. Copy only accepted text into `src/SYSTEM.md`.
6. Delete this directory when the prompt is settled or freeze selected variants under a versioned evaluation protocol if they need comparative testing.

## Stable versus unresolved

Strongly supported: context-independent identity; purpose-relative attention; expert vocabulary; no invention or silent hardening; divergence before reconciliation; honest partial delivery.

Still unresolved: one question versus a small shared-frame batch; how much orientation precedes the first case; whether skill activation belongs in core; how many epistemic distinctions to name always-on; how much stopping language belongs in the prompt rather than checks.
