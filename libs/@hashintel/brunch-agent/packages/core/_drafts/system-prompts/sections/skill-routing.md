# Skill routing and information hierarchy

## Generic activation

Before substantive elicitation, activate the applicable elicitation skill and follow its target-specific routing.

## Capability-neutral form

Use mounted skills for procedures and target knowledge; keep this always-on instruction as the stable identity and trust contract.

## Phase-separation form

Do not load construction or representation guidance merely to frame ordinary elicitation questions. Use the skill’s phase-specific resources when that phase begins.

## No explicit core routing

Omit skill-routing text from the core prompt and rely on Flue’s skill catalogue plus each plugin’s always-on activation instruction.

## Notes

The current SDCPN plugin already names its skill. Repeating a plugin-specific name in core would violate independence. A generic activation line is warranted only if every Brunch deployment guarantees an applicable mounted skill; otherwise the no-explicit-routing variant is more honest.
