## In-flight scope card

### Target behavior

A Brunch model invocation has a phase-aware progress clock. Meaningful provider events reset it; socket heartbeats do not. Production thresholds are:

| Phase | Idle threshold |
| --- | ---: |
| Request dispatch until first model event | 10 seconds |
| `reasoning_start` until its first delta or completion | 15 seconds |
| Reasoning or text after first delta | 10 seconds |
| Reasoning completion until next output item | 10 seconds |
| Function-call start until first argument delta | 10 seconds |
| Function arguments after first delta | 10 seconds |
| Cancellation acknowledgement | 2 seconds |

On expiry, the product immediately changes the speculative row from passive busy to visible recovery, aborts the incomplete upstream invocation, and awaits cancellation. If cancellation wins and no tool call was canonically admitted, the product starts at most one visible invocation with the same model and reasoning level from the latest canonical conversation tail. It does not replay the user message or any completed tool. A second idle, unacknowledged cancellation, or canonical admission winning the race terminalizes visibly red without automatic retry.

### Contract constraints

- The timer bounds **idle time**, not total response duration. A 123-second Ledger call remains valid while deltas continue.
- Meaningful progress includes reasoning/text deltas, tool-argument deltas, tool-call completion and response completion. A provider connection or heartbeat alone is not progress.
- The single 15-second exception applies only after `reasoning_start` and before its first delta or completion.
- Retry is one incomplete model invocation, not the entire submission or user turn.
- Retry uses the same provider/model/reasoning settings and a new correlated attempt/request identity.
- The old provider attempt must acknowledge cancellation before retry begins. If it does not acknowledge within two seconds, stop red rather than overlap requests.
- Canonical admission wins its race with the watchdog. Never auto-retry after `toolcall_end`, tool execution or any other canonical tool admission.
- Ignore late events from a cancelled attempt. They cannot reopen admission, update the live row or settle the retry.
- Continue from the latest canonical tail. Completed server and browser tools from earlier model steps in the same submission remain results; they are not rerun.
- Partial reasoning and partial tool arguments from the cancelled attempt do not enter canonical conversation context.
- The retry is user-visible and content-free in diagnostics. It is not a silent fallback.
- Never switch models, lower reasoning, silently retry twice, resend persona input, normalize interrupted usage to zero or manufacture settlement.
- Known and unknown usage for both attempts remains explicit.
- No paid rerun is authorized by this handoff.

### User-facing states

First idle:

> The model stream stopped making progress. Cancelling the incomplete response and retrying once…

Repeated idle or unacknowledged cancellation:

> The retry also stopped making progress. Nothing incomplete was executed.

Exact copy may be refined, but it must distinguish pending, recovering, successful and terminal-error states without exposing provider internals or implying that an unadmitted tool executed.

### Acceptance criteria

1. A deterministic native OpenAI fixture emits reasoning start/completion, function-call start and one argument delta, then remains open without function `response.output_item.done` or `response.completed`.
2. The real live channel and panel render thinking plus an `input-streaming` `mutate_workpiece` row before canonical admission.
3. Test-configured millisecond thresholds make the watchdog go red in seconds, not minutes.
4. Idle expiry publishes a typed content-free disposition with submission/turn/attempt/request correlation, phase, last meaningful event kind and idle duration.
5. The partial call is not present in canonical history and cannot execute.
6. The speculative row visibly enters recovery, then either reconciles with the retry or terminalizes red.
7. Upstream cancellation is observed before retry starts; an unacknowledged cancellation stops without overlap.
8. Exactly one same-model/reasoning retry begins from the latest canonical tail.
9. A completed tool from an earlier step in the same submission is not rerun.
10. A late event from the cancelled attempt is ignored.
11. If canonical admission wins the watchdog race, no retry begins and the admitted call proceeds once.
12. A second idle produces a terminal error and no third invocation.
13. Launcher Ctrl-C requests Flue abort and waits a bounded interval for submission settlement before stopping owned services. If the grace expires, the forced shutdown records that settlement was not obtained.
14. The retained submission row, speculative row and F.6 chronology are terminal after graceful Stop.
15. Existing healthy long-stream, guard, context projection, persona, browser/Voice and recovery owners remain green.
