Stop `@hashintel/ds-helpers` publishing empty tarballs.

`styled-system/` is `ds-helpers`' entire published payload, but it was generated by `@hashintel/ds-components`' Panda config writing straight across the package boundary with `--clean` — which empties the output directory. Because `changeset publish` publishes packages concurrently and sibling publish hooks re-run that codegen, the wipe could fire while npm was packing `ds-helpers`, shipping a tarball with only the six metadata files.

Panda now writes to a `ds-components`-private `styled-system/` directory and keeps `--clean`, so stale artifacts are still swept. `ds-helpers` materialises its payload by copying that directory: the copy is staged in a temporary sibling directory, validated against `ds-helpers`' own `exports` map, and moved into place with `rename` — never written in place — so no consumer or packer can observe a partial `styled-system/`, and a missing or incomplete source fails the build loudly instead of producing an empty tree.

`ds-helpers` also verifies at pack time that every `main`/`types`/`exports` target resolves to a real, non-empty file, and drops the `./recipes` export and the `import`/`require` conditions on `./types`, which have never resolved to a generated file in any published version.
